# S01 采购补货工作台 · 交互原型（V3.2）

## 打开

双击 `index.html`（Edge / Chrome），或本地起服务：

```bash
python -m http.server 8766 --bind 127.0.0.1
# http://127.0.0.1:8766/prototypes/s01-workbench-v3/index.html
```

单文件、无构建、无外部依赖。状态在内存与 `sessionStorage`（筛选、布局偏好），刷新会重置业务数据。

## 四个入口

| 入口 | 路由 | 回答什么 |
|---|---|---|
| 工作台 | `#/workbench` | 今天先处理什么 |
| 补货建议 | `#/suggestions` | 全部对象什么状态 |
| SKU 详情 | `#/sku/CB-1001`（Tab：`/quality`、`/history`） | 补不补、补多少、凭什么 |
| 请购管理 | `#/requisitions`（单据：`/RQ-2026-0011`） | 我提交的单据到哪一步 |

## 三种 AI 布局（顶部 A / B / C 切换，或 URL `?v=a|b|c`）

- **A**：图表 → AI（全宽）→ 分区；操作在右栏
- **B**：图表 → 分区；AI 与操作同处右栏
- **C（默认，推荐）**：结论条 → **AI** → 图表 → 分区；底部常驻操作条

对比与选择依据见 `docs/reports/S01_UX_V3.2_可视化选型与AI分区_20261114.md` §2。

## 建议审查路径（约 6 分钟）

1. **工作台**：4 个待办数字 + 对象构成环形（4 组）+ 待处理队列；点"待确认数量"应带筛选跳到列表。
2. **列表**：搜索"收纳" → 进入"旅行收纳包" → 返回，筛选仍在；注意库存列是"55 / 75 + 覆盖 4.9 天"，没有条形。
3. **详情（CB-1001）**：结论条 → AI 区（未生成，点"生成 AI 解读"看 生成中→四段结构）→ 结存折线（11-15 穿过 0 轴）→ 底部操作条。
4. **改数量**：25 触发整箱校验 → 30 要求填原因 → 勾选 → 提交，操作条立即变为"待 ERP 审批 · RQ-2026-0013"。
5. **ERP 参考**：打开 LT-3012，来源标"ERP 参考"，核对后仍可提交（方案 B）。
6. **台账**：请购管理 → 双状态列 + 进度 + 回读；打开 RQ-2026-0012，第二步为琥珀色"结果待核对"。
7. **窄窗**：拖到 1024 / 820，操作条收为一行、导航转顶部、AI 转单列。

## 图形与字段（不得替换为装饰）

| 图形 | 数据 | 说明 |
|---|---|---|
| 对象构成（左环右数） | 按处置动作分组的计数 | 7 状态在 120px 下不可辨，故归 4 组；左半环看形状、右半读数字，中线分隔；明细在 `title` |

## 自动验收（真实浏览器）

```bash
python -m http.server 8766 --bind 127.0.0.1   # 另开终端
node _e2e.cjs
```

CDP 拉起 headless Edge，真实鼠标/键盘事件，覆盖 1440 / 1024 / 820，**76 项断言**，结果见 `_e2e-result.json`，截图见 `screenshots/after/`。

另有两条数据自检（浏览器控制台可调用）：

- `__ux3check()`：每个批次"目标 − 可用 → 按 MOQ/整箱取整 = 建议数量"
- `__ux3check2()`：首次短缺日必须等于结存曲线首个 ≤0 的业务日

## 边界

- 脱敏模拟数据；`演示数据` 角标与页脚为唯一环境标识；不连接 ERP、不调用模型、不写任何系统。
- "15 天内 7 个有效业务日"未获批准，仅以"政策草案 · 未生效"展示。
- **结存与首次短缺在原型内本地推算**，只为让演示自洽；正式实现必须消费后端 B01 结果，禁止前端复刻。
- **请购列表接口尚未实现**，台账为演示态；正式实现前须补只读列表接口。
