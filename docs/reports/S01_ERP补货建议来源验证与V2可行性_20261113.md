# 教学 ERP 补货建议来源验证与 S01 V2 可行性

日期：2026-11-13。应用基线为已合并 P3 的 main `60e9cf2d53d368999936b894fa8c7f6d32352d9d`。本轮只调查、核对和设计评估，没有开发 V2、修改 B01/B02、登记新监控成员、调用模型或执行 ERP 业务写入。P3 最终验收和合并另见[验收报告](S01_P3最终验收合并_20261113.md)。

**结论：REST 建议来源为 `REFERENCE_ONLY`；本轮没有 `USABLE_FALLBACK` 样本。** 已真实找到截图指定的 **5 条非空记录，其中4条正数量、1条零数量**，页面字段与 REST 值一致。商品、库存和部分采购关联可核验，但建议算法、真实生成时刻、更新机制和有效采购抵扣仍不足。`getSummaryList` 对目标 SKU 没有返回匹配记录，目标字段映射为 `UNVERIFIED`，不能把其空集合解释成建议0件。

建议进入 **V2契约/范围设计评审阶段**，并在另行授权后分阶段开发。现有证据不足以批准“全权限SKU自动分析并直接请购”或把ERP建议作为权威净需求。本报告不构成实施授权。

## 1. 授权、身份与调查覆盖

当前 `.env.erp` 账号经真实认证及 `/api/v1/me` 核对为教学租户 **1**、管理员角色，权限返回 `*`。精确店铺查询独立确认 **店铺1／MIMI Apparel US／美国**。管理员权限只说明接口访问能力，不说明所有数据是本项目资产；本轮业务调查以负责人明确给出的5SKU为准。

每款独立查询商品、建议列表/详情/上下文、该店库存、Listing；库存都以 `tenant_id=1/store_id=1/product_id/SKU` 关联到 **仓303（美国FBA平台仓）**。商品均声明单位“件”。建议本身仅有 `store_name/SKU`，没有明确 `warehouse_id/store_id/product_id`，不能据此保证通用情况下唯一的店仓商品关系。5款 Listing 精确查询均完整空集合，因此没有已验证的MSKU/ASIN映射。

这些是**既有教学仿真记录的真实网络观察**，不是本轮工程Mock，也不是企业真实经营样本。现有data-contract声明 `kind=synthetic`、`record_policy=dataset-includes-manual-simulation`；部分商品描述也明确教学演练用途。描述只作为维护者的场景说明，不作为计算日志、已签业务规则或执行指令。

本项目正式监控仍是原自建2SKU；本轮5SKU和共享仓303没有加入ACTIVE登记。QD-S/PZ-M的采购也不属于当前P3自有仓308范围。不得用这次外部样例替换P3“自有已审批正样本未验证”的验收限制。

## 3. 两个关键异常与采购核验

**QD-S：200件在途有同SKU采购事实，但是否已被建议60抵扣，UNKNOWN。** 有界关键字查询发现采购 **1397／PO-YF-SO-QD-S-2026**，列表和独立详情一致：单行200件、已收0、待收200、状态“待到货”；采购上下文关联审批 **1805**，独立GET为“已通过”；上下文还显示送货单 **933** 同SKU200件、未收货/已收0。

该采购目标为 **仓101（华东服装仓）**，不是FBA仓303；计划到货 **2026-12-18**，晚于建议断货 **2026-12-08**。`source_plan_no=null`，按建议号精确查来源计划返回0；建议上下文也没有结构化采购关联。因此，已验证“同SKU存在200件已审批待到货采购”，**未验证“建议已生成采购单”就是1397的可追踪状态，更未证明其200件已进入建议公式**。即使数量一致，也不能忽略仓间转运、晚到风险、承诺可售时间或重复采购风险。

这里的已审批正样本在共享教学范围，不能给本项目P3自有登记范围补签正向验收。没有执行审批决定、下单、收货或入库；没有读取旧36件单。

**PZ-M：零建议不能解释为无需补货。** 实测建议0、库存0、日均6、最急；商品维护描述将其作为“ERP没算出建议，需独立计算”的演练案例。这说明样例意图，**真实计算失败原因、零值原因码和日志仍UNKNOWN**。不能把该描述当作引擎已报错的证据。

另查到现有采购 **1403**，150件、待审核、已收0；`source_plan_no=REC-YF-SO-PZ-M-2026` 为明确来源关联，独立详情与列表一致。审批 **1808** 独立GET为“审批中”，仓306，与FBA303也不同。该采购保存时间在建议之后，而建议仍是0/待确认，显示当前建议快照并未反映该单的可见状态变化；不能据此推断ERP应把未审批150抵扣，也不能认定它是零建议的原因。该单不是本轮创建，未修改或重提。

NG/PZ-L/QD-L的本次有界 `q=SKU` 采购查询均为空。关键字匹配不保证覆盖所有不含SKU文本的多行采购，故只写“本次查询没找到”，不写“没有采购”。多SKU逐行已收、取消/关闭、分批收货及有效可售剩余的建议计算关系均未取得实测证据。

## 4. 接口、批量与查询成本

| 请求 | 真实结果 | 覆盖边界 |
|---|---|---|
| GET `/api/v1/replenishment`，`field=sku&q=<指定SKU>&match=exact&store_name=MIMI Apparel US` | 5次均200，各total=1；独立详情与上下文一致 | 只覆盖5款，不是全店枚举 |
| 同接口 `ids=679,674,676,678,673` + 店铺，`limit=2` | offsets 0/2/4：2+2+1、total始终5、无重复，完整 | 验证**已知ID批量**及此小样分页；未证明全部有权限SKU可直接批量关联 |
| POST getSummaryList，真实sid=1、data_type=2、`msku_list=<5个页面SKU>` | 200/code0、total0，完整空集合 | 页面SKU是本地SKU，没有已验证MSKU；只是有界假设探查，不能算准确MSKU映射或建议0件 |
| 同POST，sid=1、data_type=2，去掉MSKU假设、length2 | 200/code0、total667，只取2条后停止 | 没有遍历667；有意不完整，两个非目标兼容行不发布/不作为成员分析；不能拿首屏断言目标不存在 |
| 同POST，sid=1、data_type=1、length2 | 200/code0、total0 | ASIN维度无可用目标样本，Listing也未取得 |

本地OpenAPI及本次在线field-catalog均把该POST声明为 `operation_class=query`、`local_resource=replenishment`、响应 `readonly_projection`；本轮仅按此只读契约调用，没有刷新/生成/维护动作。`quantity_sug_purchase` 的目录标签是“建议采购量”，但目标记录未返回，**实际字段映射、单位、时间戳和计算含义仅为Schema声明，未验证**。不能把它与REST `suggested_qty` 当成数值相等或同一计算版本。

`getSummaryList` 的MSKU/ASIN关联缺口以及兼容首屏 `msku_fnsku_list=null`，使跨接口同源关系仍UNKNOWN；Listing缺失可能相关，但没有服务实现证明因果，不能写成确定根因。REST已经返回全部5个页面样本，无须绕过接口或抓取隐藏写入口。

调查合计 **63次HTTP尝试，全部200**：3次认证、57次GET、3次已确认只读汇总POST，即60次业务读取。低频串行，有界重试上限一次，本次没有触发重试，累计未超过本轮自定80次调查边界。请求耗时和每次指纹见summary；小样可接受，不能外推全库成本或服务SLA。全权限遍历需要分页漂移、去重、缺页/超限、中断续跑和总预算设计。

当前没有503/超时；保留了兼容首屏 **2/667不完整** 事实。之前两自有SKU调查的6次503及空集合原证据完全保留，见[既有报告](S01_ERP未来销量预测接口补充核实_20261113.md)。过去为空不代表ERP无此功能，当前空集合/请求失败也不代表零建议。

## 5. 字段含义与降级准入

| 项目 | 已验证 | UNKNOWN／限制 |
|---|---|---|
| suggested_qty | 同一保存建议的整数数量；页面/REST/独立详情一致 | 是毛需求还是已扣净需求、覆盖期/算法/版本；没有可直接执行采购的保证 |
| 单位 | 5商品档案单位“件”，库存/商品ID关系一致 | 建议字段没有独立单位元数据；沿用商品件单位是有依据的解释，不能泛化到套/箱或多单位商品 |
| daily_sales | 页面和源记录值一致 | 统计天数、完整业务日、订单或履约、断货修正、历史或预测分母；未取得原销售历史独立重算，不等同本系统7完整业务日SMA |
| available/inbound | FBA库存独立核验；QD-S同SKU采购200和审批已通过可查 | 海外/FBA重复桶、库存可售质量、跨仓/转运、在途有效ETA；不得直接合计或抵扣 |
| urgency/stockout/status | 5款页面与API值一致 | 紧急度规则和断货公式；显示已生成不等于有可追溯单据/已审批/已入库 |
| generated_at/updated_at | 源时间字段及保存后稳定性可读 | generated_at未来且等于断货日，不能视为真实计算时间；周期/实时重算与有效期UNKNOWN |
| quantity_sug_purchase | Schema有“建议采购量”、只读投影标签 | 本轮目标非空值没有验证，不能替换suggested_qty |

四种结论本轮的适用情况：

- `USABLE_FALLBACK`：**0条**。需补齐可信生成时间/SLA、来源/版本、单位、准确店仓SKU关系、采购抵扣及部分收货/取消语义；再以合法变化观察或可信实现证据核验。
- `REFERENCE_ONLY`：REST的5条保存记录；4个正数可带限制显示为“ERP源建议”。零值仅显示“源记录为0，原因未验证”，不能展示“无需补货”。
- `NO_USABLE_SAMPLE`：之前自有2SKU的调查范围确实没有源建议；本轮总体不适用此标签，因为已找到5条记录。
- `UNVERIFIED`：目标getSummaryList映射、更新/净需求语义等独立子项；不能因为接口200而升级为可用降级。

允许未来分析展示至少要有：明确授权分析范围、完整页、唯一实体关联、来源ID/时间/版本、单位与缺失值区分、限制标签；来源字段不可信时只能展示参考值并进入待核实队列。已审批在途未确认、生成时间异常、跨仓不明、零值与风险冲突、无供应商/报价、字段缺失或HTTP故障时，不得生成可直接请购的候选。

本轮所有源建议 **procurementAllowed=false**。B01/B02的规则结果继续是本系统确定性结果；ERP源建议不伪装成B02计算，也不能补造需求曲线、分母或通过质量门。人工确认不补足数据准入，不代替ERP审批。
