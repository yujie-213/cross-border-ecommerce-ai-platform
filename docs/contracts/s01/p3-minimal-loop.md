# S01 P3 最小业务闭环（2026-11-13）

负责人本轮明确授权本契约范围的实现、教学ERP采购申请创建/提交和独立回读、测试、普通推送评审分支；最终REVIEW。它收缩 ADR-S01-P3-012 的后续开发范围，不改历史调查证据。

## 正式采购读取

只在 ACTIVE 自有监控范围，以已核验仓库和正式状态精确分页查询采购，再匹配租户、SKU行。禁止读取未审批采购/旧36/草稿来做检查或阻断。采用独立版本的采集标记，历史快照仍按原标记回放。

本地兼容采购契约说明：待下单表示已审核，待到货表示已下单；新适配只白名单这两个有效阶段和部分到货。未知状态不猜。范围至少包含租户/SKU/仓库；ERP缺少店铺/用途时，只有结构化字段或本系统持久化、独立回读通过的采购申请关联证明才能确认销售备货归属。供应商不是排他条件。范围不能确认的行仅报告覆盖限制，不冒充本范围有效采购。

采购总量、已收、待收分别展示；多SKU不得使用整单累计推算某行。ERP当前只有计划到货，没有已核实可售日期/剩余供给关闭语义，因此当前真实适配一律不把它当可售在途。B01/B02及既有Supply契约不改；已有规范化可靠供给仍由原引擎计算，迟到风险策略保持。

## 人工确认与采购申请

没有独立请购资源时，以 `POST /api/v1/purchase-orders` 创建待提交采购申请，随后 `POST /api/v1/workflows/purchase-orders/{id}/submit {}` 提交ERP审批。页面明确“待ERP审批”，中台人工确认不代替ERP领导决定。不注册任意写工具，不放宽D01。

新增窄用例 `POST /api/v1/analysis-tasks/{id}/requisition`，请求只接受整数最终数量、调整原因；沿用可信会话/CSRF/Idempotency-Key。GET同路径读取本报告的提交记录。授权 `s01:requisition` 与 `tasks:read` 分别校验，默认不授予写权限。仅在线自有教学新版本且有有效候选的成功报告可提交；固定包、旧规则、质量阻断、超过24小时或已退出ACTIVE的范围均拒绝。

服务器重取同范围ERP事实并经原B01/B02复算，确认候选/库存/约束未漂移，再校验MOQ、整数件、整箱与报价最低金额。价格、供应商、币种、仓库来自ERP和登记范围，客户端不能指定。保存AI原量、人工最终量、原因、主体、源报告/快照、范围/批次、ERP真实ID/状态。修改数量须记录原因，不评判理由。只销售备货。

## 持久化和恢复

复用O01公开报告读取、G01、G02及连接；新增单一业务操作表，不搭通用采购平台。一个报告只允许一个申请操作（另一个key相同内容也复用；不同内容冲突），业务号由租户/报告确定。短MySQL事务持久化发送意图并审计，网络在事务外。阶段CAS领取及有界占用避免并发发送；进程崩溃/超时不丢失原业务号。

创建发送后必须独立按业务号完整查询并核对单头/行/数量/金额，再提交；提交后独立详情回读确认状态。创建结果未知不盲重建，原号查不到仍UNKNOWN，允许重复核对。提交UNKNOWN只读核验；确认原单仍待提交时可沿原ID重试契约幂等submit。原ERP记录被修改或出现多条立即阻断。GET无ERP副作用；POST同操作可完成恢复。读不到不显示成功。

## 验证与兼容

新建增量迁移，禁止降级删除；仅获准隔离工程库。保留现有报告schemaVersion和历史重放，通过采集标记增加字段；普通off/mock与旧固定包不开放采购。单测覆盖负权限/跨范围/字段/并发/失败/UNKNOWN/漂移/多SKU/分页；工程测试用明确假ERP，真实测试单独标记。真实教学只创建并提交一张符合MOQ/整箱的新申请，独立回读和重复提交核对；正式已审批正样本若不存在不代签制造。相关回归/前端构建与浏览器通过后独立提交推送，REVIEW等验收，不合main。
