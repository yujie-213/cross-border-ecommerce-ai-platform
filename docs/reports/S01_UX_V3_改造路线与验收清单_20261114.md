# S01 UX v3：正式 Vue 前端分阶段改造建议与验收清单

- 日期：2026-11-14 · 分支 `review/workbuddy-s01-ux`
- 前提：本文是**改造建议**，本分支未修改任何 `frontend/`、`src/`、`tests/` 文件
- 关联：`docs/reports/S01_UX问题清单与代码定位_20261114.md`、`docs/ui/S01_UX_V3_IA与页面设计_20261114.md`

## 0. 总体原则

1. **不推倒重来**。后端契约、`useWorkspace`、`api/v2.ts` 的数据映射都保留；改造集中在 `App.vue` 的路由外壳与 `V2Workbench.vue` 的拆分。
2. **契约先行**。请购管理页依赖后端缺失的列表接口，先补接口再做页面，禁止前端拼装。
3. **可回退**。每一步都能单独发布；用 `?ui=v3` 开关并存新旧外壳，验证通过后再切默认。
4. **测试同步**。现有浏览器测试以旧结构为前提（见 §4），必须同步更新，不能靠改断言"修绿"。

## 1. 阶段划分

### P0 · 契约与数据（无 UI 变更）

| 项 | 内容 |
|---|---|
| 目标 | 让"请购管理"有真实数据来源；让列表能显示"已请购" |
| 范围 | 后端新增只读接口 + 前端类型 |
| 建议契约 | `GET /api/v1/s01/v2/requisitions?state=&cursor=` 返回 `items[{ no, entityKey, sku, warehouseName, finalQuantity, suggestedQuantity, state, erpStatus, submittedAt, verifiedAt, readbacks }]` + `nextCursor`；权限沿用 `tasks:read`，**不新增写权限** |
| 备选（更小） | 扩展 `GET /s01/v2/singles`，为每条历史附加 `requisition: { no, state, erpStatus } \| null`；前端再按单据聚合。缺点是同一单据会随多次分析重复出现，需要去重规则 |
| 不做 | 不做审批、不做下单、不做跨租户汇总 |
| 验收 | 接口返回真实 ERP 单据号与状态；UNKNOWN 单可被单独筛选；无单据时返回空数组而非 404 |
| 阻塞关系 | 阻塞 P3。P1/P2 不依赖本阶段 |

## 5. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| 拆分组件时丢失 `epoch` 竞态控制 | 快速切换 SKU 时旧响应覆盖新页面 | 先迁 composable 再迁 UI；保留 `V2Workbench.vue` 直到浏览器测试覆盖轮询/取消/权限拒绝 |
| 请购列表接口未就绪 | 请购管理无法真实上线 | P3 延后；P1/P2 独立发布，请购入口暂时指向 SKU 详情 |
| 删除 V1 请购面板影响回退路径 | 若需回退到非 V2 模式将缺少表单 | P3 前确认 `v2Enabled=false` 是否仍是受支持发布路径；若是，保留 V1 组件并只做文案对齐 |
| 文案改动被误读为业务变更 | 评审争议 | 本文件与设计说明均声明：改名不改变权限，"人工确认"仍不等于审批 |
| 政策参数提前硬化 | 未来政策变更需返工 | 按 §5 结构，`draft → requirement` 只是数据字段升级，页面结构不变 |
