# 智能售后与客户体验 V1.0 使用与运行

本分支提供正式 Vue 售后模块，复用中台登录、首页、API、独立 Worker 和一键启动。原型方向已确认，最终功能仍待负责人和星星统一验收；状态以 [TASKS](../TASKS.md) 为准。

## 启动与首次启用

当前开发机已显式完成 B 迁移及 admin 增量授权。直接双击根目录 `Start-Platform.cmd`，用原 admin 密码登录，从首页进入「智能售后与客户体验」。默认地址 `http://localhost:5173`；本次开发机保留原有端口配置，实际为 `http://localhost:5175`、API8768，以启动器显示为准。停止使用 `Stop-Platform.cmd`。密码、既有会话及 S01 授权不需要重置。

新环境先按 [README](../../README.md) 完成已有本地平台配置，然后显式执行：

```powershell
.venv/Scripts/python.exe -m commerce_hub.entrypoints.enable_after_sales
.venv/Scripts/python.exe -m commerce_hub.entrypoints.enable_after_sales --apply
```

默认 dry-run；apply 前向迁移至 `0013_b_workflows`，给实际 admin 添加 B 的 15 项动作授权，保存只读 ERP 配置并打开 B。正式读取范围与补货共用 MonitorRegistry 的已核验自建登记成员；可读店铺目录和SKU前缀不能扩大范围。已有 B 授权变化或撤销时拒绝覆盖，需管理员显式修订。普通启动不迁移、不自动补权、不读取 ERP。现有密码、主体、会话、S01 grant 的指纹在显式启用前后核对一致。

`data/private/local-platform/runtime.json` 的 `afterSalesEnabled` 控制模块；关闭后 S01 可继续使用。B 源配置错误只使对应取证能力不可用。私有文件禁止外传。

## 建议体验顺序

1. 「知识与资料」→「导入完整教学资料」：导入固定 40 订单、2 商品的独立教学包，后台执行完整性校验和独立回读；成功后由人工「启用资料」，已停用且指纹未变的版本也可重新启用。点击准备四类教学政策，逐项核对后提交审核、发布。草稿不参与检索，教学政策不等于企业正式政策。
2. 「售后工作台」→ 记录来源选“独立教学体验” →「教学与异常演示」：选择教学版本及订单、填写客户陈述，保存并核实事实。可靠单一商品自动关联；多商品才选择本订单受影响商品。纠正已有关联须填写原因。检索政策后可保存人工处理、退回补充或升级，历史保留原稿与处理者。无 B 模型许可时明确显示建议未生成，继续人工处理。
3. 「体验与退货分析」→ 记录来源选“独立教学体验”：选择启用版本，开始分析。固定上衣样本从上期 `1/40` 到本期 `12/40`，增加 `27.50` 个百分点；另一商品 `1/40 → 1/40`。统计由确定性代码计算。查看反馈原文、人工修订主题，选择证据并发起调查。普通页面自动使用已核资料的对比期间，不要求填写窗口 JSON；判定说明可展开，支持与历史报告比较，原报告不会被覆盖。
4. 「质量风险」：补充调查证据、记录人工结论，登记疑似风险，再由人工确认。只有确认且在有效期/来源/店仓范围内的风险才进入补货提醒；可驳回、关闭、撤销。教学商品进入真实教学 ERP 补货页面前，必须完成精确商品/店铺/仓库映射和独立只读核验绑定。绑定在资料管理折叠区：选择教学商品，搜索精确 ERP SKU，选择已核商品与店仓，再执行独立回读；不要求 JSON，也不能靠 SKU 前缀自动匹配。当前真实 ERP 绑定未实测；独立合成 ERP 适配器的单品/批量联动已走通。

售后工作台/处理页直接展示获准 ERP 工单，客户体验页直接展示评价和订单反馈，可选店铺并有界更新。评价按准确 SKU 和唯一租户商品自动关联；订单反馈有可靠 order_id 时独立核实所属订单，related_id/no 不推断成订单。缺订单/仓库明确未知；仅多商品或异常才人工确认。人工补充中仍可接入精确工单 ID。工单标题不代表完整会话；缺字段、歧义、截断和来源读取失败会显示待核实。真实 ERP 原生完整成熟退货群组尚未取得，分析流程使用明确标记的中台教学包，不宣称真实 ERP 退货率。

## AI、政策与外部动作

售后建议、反馈主题及原因解释已接入 A01、O01 预算和持久用量凭据。B 默认不联网，独立授权必须明确三种用途、调用数、Token 和金额预算；不能使用 S01 的许可。授权配置由本机管理员在 `data/private/b-after-sales/model-authorization.json` 设置，与既有模型凭据共同生效，格式与校验见 `src/commerce_hub/bootstrap/after_sales.py`；不得从网页自授。负责人本轮已明确允许 B 模型，当前本机已启用，前次14次调用及历史失败保留；本次另6次/11536 Token真实调用，分类/解释/政策草稿及人工审核正例通过，失败及实际费用 UNKNOWN 保留；不是企业正式业务验收。配置只在本机私有目录，S01授权不挪用。

政策按分类、地区、平台、语言、业务时间和适用性检索，不使用向量库。建议仅引用当次已发布版本；失效、撤销、事实变化后旧建议不能采纳。安全信号优先升级人工；AI 不计算权威比例或金额、不确认缺陷、不承诺退款。客户消息、退款和 ERP 业务写入均无自动执行入口。

## 持久化与恢复

资产、版本、审计、分块、命令键及任务步骤保存 MySQL；网络在数据库锁外。并发修改使用 revision，重复命令按原键查结果；未知发送不可换键盲重发。页面保留待核对命令路径/键，敏感正文不存会话存储。重启后可从后台任务与历史继续，预算和截止时间不重置。

教学数据封存后不可覆盖；迟到数据使用新版本，缺块/冲突/不守恒进入阻断或隔离。停用数据集、撤销授权或绑定后，风险读取及历史披露重新检查权限。补货当前提醒与分析时历史风险分列；超过新鲜度提示刷新，不把读取失败显示为无风险。风险只提示，不改原 B01/B02、补货数量、候选或请购准入。
