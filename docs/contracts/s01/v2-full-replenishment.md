# S01 V2.0 需求、架构与接口冻结 v1

2026-11-13；负责人完整长任务及范围补充授权。基点main e3591aacb96aca7d90b1f4e5e9efcfa5942eed14，独立分支codex/s01-v2-full-replenishment，最终REVIEW不合main。此增量作为当前V2需求/架构/API依据，既有冻结正文和历史调查不重写。

## 需求和范围

目标为全部当前教学租户内获准可读店铺/仓库/SKU的人工批量检查、单品按需AI、人工请购闭环。负责人已明确全租户获准只读分析，不以自有2SKU、截图5SKU或单店作为最终范围。ERP实际资源/行权限优先；显式租户校验、枚举完整性、每对象终态和覆盖率，禁止静默漏项。采购仍仅既有自有教学授权范围；账号技术权限、分析权限和采购权限独立。

F01动态身份以租户/店/仓/商品ID建立；无Listing不得忽略。商品孤立/同SKU多档/店仓映射歧义也生成不可执行结果。F02人工批量持久任务及取消/恢复/重试/历史/分页。F03规则优先，失败保留原因后读取ERP建议，不降低B01/B02质量。F04方案B：REFERENCE_ONLY/算法或周期UNKNOWN不单独阻止请购；必要采购约束、正式采购事实、可靠归属、正整数/明确单位、有效报价和人工确认仍强制。F05同口径有依据风险排序，来源不可比则分组/待核实，不造统一分数。F06只有主动新建单品才实时采集及经A01解释。F07沿用Vue设计体系，批量→摘要/筛选→详情→单品AI→人工确认→ERP真实回读。

## 架构和数据所有权

O01继续唯一任务/预算/期限/发布；注册S01_V2_BATCH与S01_V2_SINGLE两个ScenarioHandler；独立Worker通过同一持久投递执行。不复制任务引擎。批量只有摘要进入O01报告，逐SKU结果及检查点由S01独立表维护，避免超过报告容量。D01管理任务内分页采集/请求额度/响应私有引用；D02解析动态身份和经营投影；D03不可变采集清单及摘要；G02保留审计；B01/B02函数与Golden不变。

目录集合是明确的collection资源，G01任务scope使用专用catalog资源标识，不能冒充某个真实SKU或通配授权。所有逐项读/单品创建/请购必须再经服务端V2授权策略核对真实源租户、当前资源授权和分析/采购范围。禁止客户端传入源凭据、采购供应商/价格/状态或扩展权限。

增量0009新增任务内采集检查点/结果表，0010新增不可变D03清单表，原8条迁移及历史报告保持；禁止破坏性降级。网络不跨SQL事务。请求预算在原task采集台账持久扣减，恢复不重置；分页/参数/行内容漂移和源失败明确暴露。任务内保存采集不是全局缓存。取消/权限撤销/期限校验在页和对象边界生效，已完成结果保留，未处理对象显示未完成。

ERP读适配先小样确认，完整枚举产品、店铺、仓库、库存、建议及有效报价；销售按完整业务日区间统一读取，正式采购源端限定已审批有效状态，不读取待审/草稿作为额外阻断。优先复用共用采集并按真实ID索引；只对需要严格规则核验的销售/流水补证一次，禁止每SKU完整重复采集。每页有界、稳定ID去重/total一致，店/仓无唯一关联明确隔离。SKU全集以商品及可见库存/建议联合发现，保留无库存/无Listing商品，不将行数量误称独立商品数。

规则数据保留最近7完整业务日SMA及独立履约/库存/流水验证；没有可靠完整历史/库存语义则规则BLOCKED，走显式ERP参考渠道。缺失/0/失败不同。现有自有登记只提供已验证期初来源/策略元数据，库存/销售/采购ID不再用于限定发现。新SKU也使用相同投影/质量和B01/B02，不能另写供需算法。已审批采购只有范围、逐行有效剩余和可售日期确定才抵扣，否则展示UNKNOWN。

## 结果、排序与采购

逐对象结果含entityKey、真实租户/店/仓/商品ID、SKU/名称、scopeEvidence、analysisState、sourceGrade、quantity/unit、observedInventory、sales/forecast、formalPurchases、constraints、uncertainties、quality、riskGroup/riskBasis、snapshotRef、procurementEligibility。来源RULE_CALCULATED/USABLE_FALLBACK/REFERENCE_ONLY/UNAVAILABLE/UNVERIFIED独立于采购资格。ERP quantity_sug_purchase未验证不启用；REST保存时间/实际语义分别记录，未来generated_at不当真实生成时间。

规则无缺口且可靠才NO_REPLENISHMENT；ERP0或空/失败不自动归此类。风险分RULE_CONFIRMED、ERP_SOURCE、UNVERIFIED，组内按各自可证明日期/提前期/源紧急度稳定排序；同组不可比仍待核实。

方案B服务端在提交前复读身份、库存、建议/规则依据、报价、商品约束、正式采购并检查显著漂移；来源变化、正量消失或硬约束冲突拒绝。算法/生成周期/是否已扣采购UNKNOWN显著提示并保存人工认知确认；已知重复采购和范围冲突不能静默忽略。原建议、人工最终量、改量原因、来源等级/未知清单和确认主体独立留痕。采购复用P3唯一操作/原业务号/阶段CAS、创建与submit、独立回读及UNKNOWN原键核查；不执行decide/place-order/收货/入库，不新增待审阻断。

## API v1（V2命名空间）

- GET /api/v1/s01/v2/options：是否启用、分析/采购范围描述、来源/限额；不在options发ERP网络请求。
- POST /api/v1/s01/v2/batches：可信会话+CSRF+Idempotency-Key，创建批量O01任务；不接受AI/采购开关。
- GET /api/v1/s01/v2/batches：当前授权集合任务历史，游标分页。
- GET /api/v1/s01/v2/batches/{id}：O01状态、采集完整性、已发现/处理/各来源/失败/未完成/覆盖率。
- GET /api/v1/s01/v2/batches/{id}/items：分页+SKU/商品/店/仓/状态/来源/风险筛选和排序；服务端完整结果集过滤。
- GET /api/v1/s01/v2/batches/{id}/items/{key}：最小公开证据和分析详情，不暴露原始ERP记录。
- POST /api/v1/s01/v2/batches/{id}/cancel；POST .../retry：原任务取消/显式新任务重试，旧结果保留；崩溃恢复原task预算不重置。
- POST /api/v1/s01/v2/singles：指定获授权历史entityKey并重新采集最新事实，只该入口允许A01；GET .../singles/{id}读取报告及同对象历史。
- POST/GET /api/v1/s01/v2/singles/{id}/requisition：独立s01:requisition、明确sourceAcknowledged、最终正整数数量及调整原因；沿用P3持久幂等与真实回读。

批量模型预算固定0、写适配不装配。单品每task最多1次/24000Token/$0.05预约，共用独立V2开发验证授权s01-v2-20261113-r1，最多4次/96000Token/$0.20；单并发30秒，不增加或重置旧账本。真实调用须本机凭据及显式启动开关；未知发送不盲重发，费用UNKNOWN保留。工程测试可以显式Mock，不能代替真实模型验收。

真实写仅自有教学资源及必要验收，不修改共享5样本。真实创建/submit最多一张必要合规申请，重复/丢响应/重启使用同一操作；缺写许可项NOT_RUN不伪造。浏览器实际走批量、筛选、单品AI、人工确认、ERP回执，原始敏感记录私有，公开脱敏结果和截图。最终完整产品REVIEW，普通推送独立分支，main不动。

统计版本v2-counts-v2按SKU字符串去重，另报商品ID数和店仓对象数；旧实验v1按商品ID+SKU组合统计，读取历史时保留原口径，不能混称独立SKU。有效分析覆盖率只计规则建议、ERP正量参考与规则无需补货；处理覆盖率包含已明确无法分析对象。

同一店仓商品出现多条库存记录时，没有可相加的独立库存桶依据则available为UNKNOWN，采购硬约束INVENTORY_BUCKET_RELATION_UNCONFIRMED。保留每条真实ID与源建议，不猜测总库存；单一记录的available也必须为非负整数。这是事实冲突校验，不是ERP算法UNKNOWN的额外禁购门。
