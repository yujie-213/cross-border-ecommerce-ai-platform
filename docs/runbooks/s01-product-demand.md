# 自有商品补货分析使用说明

适用 `codex/s01-product-demand-rebuild` 评审版，最终状态以 TASKS 为准。原V2全目录手册保留历史，本版默认仅分析登记自有商品。

1. 双击仓库根目录 `Start-Platform.cmd`，使用既有本机 admin 密码。以启动器显示地址为准；本轮独立验证地址为 localhost:5175，其他旧实例不会自动加载本分支。
2. 工作台点击“重新检查自有商品”。批次会联网读取清单内最新事实，显示不同SKU数和店仓数；批量零模型、零采购写。历史批次不会重算。
3. 点击“需补货SKU”“暂不补货SKU”或“缺货风险SKU”进入对应商品。列表按SKU聚合，计划合计只表示各仓独立计划之和，不是库存池。
4. 打开商品详情，在逐店仓表点选“分析此仓”。下方的可信历史、未来周期情景、当前库存、风险、ERP对比都随店仓切换。未知日期不补零，低样本/陈旧/缺库存会披露限制。
5. 区分未来需求、参考库存补充量、MOQ/整箱后的采购候选和人工最终量。缺报价等采购条件不会阻止前两项分析；缺可信库存时只预测需求。
6. “刷新当前店仓分析（不调用AI）”独立重读该店仓，结果和历史保存。主动“生成AI解读”才尝试模型；模型不可用时参考数字和规则原因仍可查看。
7. 请购资格仅供核对。提交仍要求获准范围、有效报价、MOQ/整箱、金额、人工确认、正式采购核对、最新事实重读、幂等和写后回读。本轮没有执行真实采购提交，不要为测试另建单据。

当前真实清单：HL-CBL100-2M、HL-MUG350-WH；两个对象同属一个登记店仓。只读取全部登记 salesIds，取消固定日期截断；不声称覆盖租户全部相关订单。新增订单/仓库先走登记核验流程，名称或SKU前缀不自动赋予成员资格。

ERP未提供适用建议时显示“ERP未提供”；不是ERP建议零件。ERP算法未知时只比较可比数量，不编造差异原因。正式采购可售日期/店铺归属未知时不抵扣，页面注明该假设，采购人员应防止重复备货。

取消/失败会保留已完成结果，不能当成完整分析。显式重新检查创建新批次；自动恢复沿原期限、预算和登记摘要，成员或源权限变化会阻断。旧共享报告可以显式回看，但不作为当前清单覆盖证明。

当前教学数据判断只作参考，企业四门继续独立准入。完整交付与限制见[产品报告](../reports/S01_自有商品补货决策产品交付_20261114.md)。
