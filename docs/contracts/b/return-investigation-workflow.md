# 退货与商品调查流程（2026-11-17）

负责人在当前对话确认：先完成四入口及业务流程，再补数据验证。此次为现有 B 业务的增量；补货计算与采购契约不变，不增加主管审核。

- 工作台处理客户问题；AI 产出客户可读回复，客服编辑确认。评价/反馈只追加 ERP 内部处理记录并独立回读，不表示已向客户公开发送。
- 退货订单按已登记销售 ID 获取正式 ERP 退货列表、详情和 SKU 明细。整单原因保留原文，调查明确到 SKU；多商品不共享缺陷结论。
- 商品监测比较相邻销售业务日期批次，分母仅完整发货件数；分子为该批次销售对应、截至所选日期已有实收时间的退货件数。草稿、授权、退款但无实收不计。评价按其自身业务日期单列。此为当前观测率，不是成熟群组最终退货率，不替换冻结 B01 指标。
- 默认两期各 7 天，可选 14/30 天；两期各至少 20 件发货且读取完整，实收退货率升至少 10 个百分点且本期至少 3 件则提示调查。低星 ≤2 星；两期各至少 3 条评价，本期低星数增加至少 2 条且占比升至少 20 个百分点则提示调查。缺失/歧义阻断判断，不当作零；小样本仍可由人发起严重个案调查。
- `POST /return-cases` 必选 SKU；`POST /monitor-cases` 固定店铺、SKU 和对比窗口。来源形成可独立刷新、可追溯的 CASE；同源或同租户/店铺/商品/SKU 的活动调查优先复用，追加相关来源。
- `POST /investigations/{id}/evidence` 保存人工陈述、证据位置、操作者与时间；追加后重新进入调查。`GET .../facts` 汇总原始来源、相关来源和人工证据。AI 只提供受证据约束的线索，人工记录结论；上下文有界且保留完整原文。任务完成不等于模型成功。
- `POST /investigations/{id}/confirm-risk` 在版本、权限、SUPPORTED 人工结论、来源和证据校验通过后，原子创建并确认提醒。记录最终引用证据快照；同调查避免重复活动提醒。继续兼容旧风险接口。撤销/过期后不再作为当前补货风险。
- 补货只消费既有 QualityRiskReadPort；单仓或本店全部仓需人工明确。无新增补货列表状态、计算约束或采购动作。

必要教学数据使用独立批次和正式 API，但复用既有店仓供应商。实际过账时间与虚构销售业务日期分开审计。内部 local_only 退货授权/实收用于验证；不退款、不通知客户、不创建采购、不代签质量风险，不直接 ERP 数据库。评价正文无创建接口的缺口保留，不用工单伪造评价样本。
