文档编号：YF-BIZ-002｜版本：2.6｜日期：2025-11-03｜适用角色：业务、产品、研发、测试及项目协作人员。先理解业务，再理解系统分工，最后理解AI怎样辅助判断和协同。

01 总流程：生意怎样运行，AI怎样参与

跨境电商通过线上渠道连接不同国家或地区的买卖双方。本指南以卖家采购商品并面向境外消费者销售为主线。完整经营过程包括市场判断、商品准备、刊登获客、采购备货、跨境运输、到仓质检、库存管理、订单履约、配送、售后、结算以及下一轮经营计划。采购与销售通常并行，售后与结算发生在不同时间，不能把它们理解为所有订单都按同一个按钮顺序办理。

企业已有 ERP、OMS、WMS、CRM、财务及渠道系统。本项目建设的智慧 AI 平台从这些系统读取授权数据，关联同一商品、订单、客户和时间窗口，帮助团队看见跨部门原因、比较方案、安排协同并追踪结果。原系统办理业务，AI平台形成可查证的综合判断；审批后的有限动作回到原系统创建草稿或内部工单。

销售渠道回答“买家在哪里下单”，履约方式回答“谁保管、谁拣配、谁交付”。同一渠道可以使用平台仓，也可以使用卖家自营仓或第三方仓。不能把渠道名称当成仓库类型，也不能因为两个页面都显示同一SKU就把它们的库存相加。

P0读取已授权的SELF_OPERATED与PLATFORM_FBA库存，分别展示；补货计算以选定仓库范围和权威来源为准。第三方仓如以统一WMS标准接入，仍须在接入台账写明运营责任。平台不建设仓库操作台，也不替代原系统已有的拆单、换货或其他功能。

ERP负责商品、供应及采购，OMS负责订单与售后事实，WMS负责库存及履约，CRM负责客户与工单，财务负责费用结算，渠道负责刊登和营销数据。这是本项目的逻辑分工；一个实际软件可以承担多个角色，权威来源必须逐数据域确认。需要回原系统处理时，平台提供有权限的来源链接和证据，源系统再次鉴权。

3.1 一个对象为什么有多个编号

一件商品可能有ERP商品ID、内部SKU编码、店铺Listing ID、渠道ASIN/商品编号及WMS货品ID；这些标识用途不同。平台canonicalId把确认属于同一业务对象的记录关联起来，但不会替换原系统编号。同名BOX-A在两个租户中仍是不同对象；不同颜色或规格不能按近似名称合并。

订单同样有渠道订单号、OMS ID、WMS包裹ID和CRM工单ID。一个订单可有多个包裹、多次退款和多个工单。按订单关联不表示所有记录一一对应；统计投诉时要先确定按工单数还是去重订单数计量。

3.2 三种时间各有什么作用

sourceUpdatedAt说明源记录何时变更；asOf说明事实或快照对应哪个时点；observedAt说明平台何时接收。coverageThrough说明该数据域已完整同步到何时。今天刚抓到昨天的库存，不能标为“今天实时库存”；供应商资料半年未变，也不意味着六个月没有同步，须看完整覆盖时间。

业务交接最少包含：对象及来源编号、已确认事实、未确定事项、当前责任岗位、下一步及期限、可查证据。AI建议必须额外说明分析范围、数据时间、关键假设和不确定性。业务人员纠正来源资料后，平台重新同步和分析，不在报告里手工把原始数值涂改成期待结果。

04 市场与选品：先判断生意是否值得做

输入与角色

运营提出商品机会，采购确认供货可行性，财务检查成本，客服提供真实使用反馈。输入包括渠道需求线索、已有商品表现、客户问题、候选规格、供应商报价和交期。热度是线索，不能单独证明可盈利或能交付。

原参考图未随文档提供；请参阅当前架构文档图示。

图示从需求证据出发，确认规格与供给，再估算成本与交付；条件不足就补证或调整。它描述选品业务判断，不表示AI平台拥有自动批准商品立项的权限。

分流程

  1. 说明目标人群和问题，把“市场大”变成可验证假设。
  2. 看同类商品销售、评价与投诉，分清短期促销和稳定需求。
  3. 核对规格、包装、供货稳定性及运输限制；待核事项交对应负责人。
  4. 将售价、商品成本、平台费用、履约与售后情景放在同一货币口径下比较。
  5. 决定继续打样、补充证据或暂缓；保留判断条件和责任人。

交接与异常

交给商品准备环节的是已确认规格、供货线索、成本假设与待决问题，不是“AI说值得做”的一句话。样品与页面承诺不符时先回到规格验证；成本资料不完整时报告必须显示缺项，不把未拿到的费用当零。

AI协同与案例

P0可以从既有商品的CHANNEL表现、CRM反馈与FINANCE贡献找线索，但不建设外部全网选品爬虫或合规审批系统。比如销量增长但“尺寸与描述不符”投诉增加，应同时检查页面描述、供货规格与退货费用，提出调查假设；不能只根据热销就建议扩大采购。没有竞品授权数据时不生成竞品销量数字。

05 商品准备：让不同系统认出同一个对象

原参考图未随文档提供；请参阅当前架构文档图示。

图中先识别Listing与SKU，再核对仓库和供货关系，最后由负责人确认映射。一个SKU可以对应多个店铺Listing与供应商，但各仓库存、各供应商MOQ和交期分别保留。图中的内部SKU指企业已有主数据及平台规范标识，不表示平台重建商品或库存账本。

输入与角色

ERP商品负责人确认商品编码、单位、规格、启停状态及供应关系；渠道运营维护Listing；WMS维护仓储识别；集成人员在平台登记对应关系。输入是原系统已存在的正式主数据，而不是要求本项目重新开发商品档案管理。

分流程

  1. 确认一个最小库存单位代表什么，颜色、尺码、套装不能混淆。
  2. 核对ERP商品与供货关系，明确MOQ、packSize和交期。
  3. 为不同店铺Listing关联正确商品；同一Listing不能同时指向两个有效SKU。
  4. 核对WMS货品与仓库映射，确认数量单位一致。
  5. 平台保存已审核映射及版本，通过订单和库存样本验证关联正确。
  6. 发现错误时先定位影响范围，再由原系统或映射负责人纠正，重放并生成新投影。

交接与异常

交付的是可追溯的身份关系和映射版本。缺映射的记录进入隔离区，不能临时按商品名称猜测。外部编码改变时保留旧码历史关系；历史订单不能因为今天修改映射就悄悄变成另一个商品。

AI协同与案例

AI可以描述映射冲突和受影响范围，但正式关联必须确认。店铺A的白色收纳盒与店铺B的蓝色收纳盒名称很接近，只有白色对应BOX-A时，蓝色不能并入BOX-A需求。若误合并，会同时扭曲销量、库存、退款主题和补货建议；因此映射错误是跨场景问题，不只是资料页小错误。

AI协同与案例

输入与角色

渠道接收交易，OMS组织订单，WMS组织仓内作业。运营关注服务承诺，仓库关注可发与拣配，客服处理买家问题。平台读取订单、承诺时间、仓库状态和CRM信息，将履约链放在同一视图。

分流程

  1. 渠道交易进入OMS，核对商品、支付、数量与客户必要信息。
  2. OMS/WMS按现有策略分仓、占用库存，处理缺货和地址问题。
  3. 仓库按任务拣配复核、包装并确认出库。

AI协同与案例

已过承诺发货时间、OMS仍待发而WMS无出库证据的订单应列为风险。结合库存和CRM催单，可说明“源数据表明缺货”或“库存可售但仓内任务待核实”。不充分的证据要列候选原因，而不是认定某部门失职。可建议CRM内部工单安排协调，但平台不替代原系统分仓、取消、改地址或出库。

12 配送交付：事件记录与客户感受结合看

输入与角色

物流事件提供包裹位置和状态，OMS提供承诺，CRM记录催单与反馈。承运商可能多次发送同一事件，也可能迟到或乱序。原WMS/物流系统负责运输事实，平台负责识别跨系统风险。

分流程

  1. 将每个包裹与订单关联，核实是否还有其他有效包裹。
  2. 接收出库、揽收、运输、派送、签收或异常信息。
  3. 对停滞、地址待确认、拒收、丢失调查分别明确负责人。
  4. 结合客户承诺和CRM沟通记录安排处理优先级。

案例

13 客户与售后：退款、退货、投诉各有证据

原参考图未随文档提供；请参阅当前架构文档图示。

按实际处理方案选择资金线、实物线和问题线，不要求所有诉求都走退货。退款以支付侧结果核对，实物以WMS收货质检确认，客户问题由CRM跟进；成本转回以财务来源为准。AI仅归纳脱敏主题、关联订单履约和观察重复问题，候选原因需要业务核实。

输入与角色

CRM承接咨询与投诉，OMS保留退款/退货业务事实，WMS处理实物回仓和质检，财务确认资金与成本结果。客户体验是跨系统过程，不只是客服工单状态。

  1. 客服确认问题、原订单和诉求，敏感信息留在原授权系统。
  2. 核对商品描述、履约记录、历史沟通与售后范围。
  3. 按原OMS/CRM流程决定退款、退货、调查或其他处理。
  4. 退款依据支付侧结果确认；实物依据WMS收货与检验确认。
  5. CRM跟进客户问题并结案，财务按实际费用/成本处理。
  6. 平台把匿名反馈主题与商品、订单、履约和贡献关联，观察重复问题。

钱和货的两条线

只退款不退货、退回待检、退回合格、退回破损是不同组合。退款成功不会让库存自动增加，退货入仓也不会证明退款完成。商品成本转回必须有财务来源；仅凭“退货已收”不能给贡献加回成本。

AI协同与案例

同一订单可能先咨询、再投诉、再催退款，三条工单不是三位受影响买家。平台按成熟签收订单群组计算投诉订单占比，再展示主题分布。100张符合观察窗的订单中12张有投诉，比例12%；这不是“12%的商品已被鉴定有缺陷”。若12张中8张关联物流延迟，应调查履约环节，不能把它们全算商品质量问题。没有批次信息时不能声称某个生产批次有缺陷。

平台可以创建内部质量调查工单，归纳脱敏证据；不会自动发道歉邮件、承诺赔付或退款。模型主题分类不确定时标UNKNOWN，留给业务复核。

15 补货与改进：让分析回到原有业务体系

输入与角色

运营、采购、客服和财务把跨系统问题提交到分析工作台。平台用规则保证数字一致，用AI提炼证据、候选原因与方案。经理对具体参数、范围和证据审批；执行人员触发已批准动作，原系统继续完成业务。

完整协同分流程

  1. 选定对象、时间窗口与问题，不用“全公司所有数据随便分析”的模糊范围。
  2. 检查来源完整性和数据时间，缺数据先补齐。
  3. 固定快照，计算需求、可售、供给、投诉与费用。
  4. 形成方案及限制，区分确定事实、假设和待核事项。
  5. 用户确认动作参数，提交另一授权人员审批。
  6. 执行前核实当前权限、原系统条件及批准是否过期。
  7. 原ERP创建采购草稿或原CRM创建内部工单，保存回执。
  8. 原系统按既有流程继续办理，平台跟进业务状态与效果。

18 术语速查

术语用于辨认业务问题和系统责任。下面的“本项目用法”是当前契约，不代表所有平台的默认口径。涉及贸易、税务和合同的术语只解释基础含义，实际办理由对应负责人按适用规则确认。

18.1 商品渠道

术语与英文 通俗解释 本项目用法与边界
SKU — Stock Keeping Unit，库存单位编码 企业用来区分、管理具体存货的编码。Amazon 说明 商品事实在ERP；不同租户同名BOX-A不能关联。
SPU — Standard Product Unit，标准产品单元 把具有共同主要特征的商品归成一类，具体规格再分成 SKU。腾讯云术语说明 商品归组信息由原系统提供，不自动把不同SKU库存合并。
Listing — 渠道商品刊登记录 在销售渠道上展示和销售商品的一条记录，通常关联商品描述、标识和报价。Amazon 刊登指南 确认渠道/店铺映射，未知映射进入隔离，不能让模型猜测。
ASIN — Amazon Standard Identification Number Amazon 分配的 10 位字母数字商品标识。Amazon ASIN 说明 用于识别 Amazon 目录商品，不能直接代替本公司的 SKU，也不单独表示某卖家的库存。
GTIN — Global Trade Item Number，全球贸易项目代码 GS1 体系中标识可定价、订购或开票的贸易项目的号码。GS1 定义 商品条码常承载 GTIN；内部 SKU 与 GTIN 用途不同。Amazon 的适用要求须按类目核实，不能推断所有商品都无例外地必须新增号码。
FBA — Fulfillment by Amazon 卖家把货送入 Amazon 履约网络，由其承担相应拣配、发货及售后服务。Amazon 对照说明 独立平台仓来源；不计入自营仓可售和补货抵扣。
FBM — Fulfilled by Merchant Amazon 订单由卖家负责组织履约。Amazon 对照说明 卖家可使用自身设施或合作服务完成配送；不要理解成只能由卖家员工亲自送货。本项目不据此承诺已接通 Amazon 生产接口。
销售渠道 — Sales Channel 商品接触买家、产生订单的销售入口，如平台或独立站。Shopify 渠道说明 渠道回答“订单从哪里来”；仓库回答“货从哪里发”，两者不能当作同一字段。
店铺 — Store / Seller Store 本项目用于区分同一渠道内具体经营账号或店铺的数据归属。 同一公司可以有多个店铺；渠道、店铺和渠道商品标识共同帮助确定 Listing 映射，不能只按商品名称匹配。

18.2 采购库存

术语与英文 通俗解释 本项目用法与边界
PO — Purchase Order，采购单 向供应商明确要买什么、买多少及约定价格的业务单据。SAP 采购说明 原ERP负责采购生命周期；平台仅可经审批创建草稿。
MOQ — Minimum Order Quantity，最小起订量 一次采购或订购需要达到的最低数量；最小量和数量倍数可以是不同规则。Shopify 数量规则 最低起订量与packSize分别校验；MOQ15、pack10时至少20件。
提前期／交期 — Lead Time 从确定的起点到货物达到约定可用节点所需的时间。Oracle 库存参数 须确认起点与终点；补货用预计可售日而非到港日。
安全库存 — Safety Stock 为需求波动或到货偏差预留的缓冲数量。Oracle 库存参数 P0安全天数乘基线日需求；不是冻结库存。
再订货点 — Reorder Point / ROP 库存位置降到某个水平时，触发补货判断的门槛。Oracle 补货策略 P0采用窗口目标和逐日余额，不直接照搬外部ROP策略。
在库现货 — On Hand 标准投影中指已实际记入该自营仓的物理总量，包含预留、冻结和不可售。 权威WMS事实；ERP镜像不能与其相加。
已预留 — Reserved 标准投影中指已经分配给具体订单、尚未出库的数量。 由原OMS/WMS维护；新增需求不能重复扣除已占用订单。
冻结 — Frozen 标准投影中指暂时禁止销售、等待规定业务处理的在库数量。 标准投影与不可售互斥；来源重叠必须转换并留证据。
不可售 — Unusable 标准投影中指已在库、但不能作为正常可售商品使用的数量。 有实物不代表能销售；平台不提供库存报废动作。
在途 — In Transit 运输语境下指已发出、尚未在目标地点完成接收的货物。SAP 调拨说明 运输在途与已批准未发运供给不同；均不能提前计现货。
可售／可用 — Available 标准投影中为当前自营仓还能用于新订单分配的数量。 available=onHand−reserved−frozen−unusable；平台只复算核对。
分配 — Allocation 原OMS/WMS为订单确定履约来源及库存占用的业务动作。 原OMS/WMS确定履约仓与占用；平台只分析分配结果。
盘点 — Stocktake / Inventory Count 把现场清点数量与账面数量核对，找出差异。 差异在原WMS调查和调整，AI不能直接改余额。
调拨 — Stock Transfer 把同一企业的货物从一个仓库移到另一个仓库。SAP 调拨说明 源发出不代表目的已收；平台不办理调拨。
补货 — Replenishment 根据需求、库存和可确认供给，安排后续可用货源。Oracle 补货策略 分析数量与到货时点，批准后可创建ERP草稿，原流程继续审批。

18.3 物流贸易

术语与英文 通俗解释 本项目用法与边界
3PL — Third-Party Logistics，第三方物流 企业委托外部服务商承担仓储、配送等部分物流工作。DSV 术语表 第三方仓可以帮忙拣货和配送；外包操作不消除企业对订单、库存和结算的核对责任。
主流向 — Head Haul / Headhaul；“头程”易混词 航运英文通常指一条贸易航线货量较大的方向，与返程 Backhaul 相对。Maersk 官方释义 本文中文“头程”指国内备货点至海外仓等前段运输。它与 Head haul 不严格等义；对外询价要写清起止点及运输段。
尾程／最后一程 — Last Mile 从当地配送节点把包裹送到最终收货地点的最后一段。DHL 释义 不是长度固定的一英里；“进入尾程”仍不等于买家已签收。
ETA — Estimated Time of Arrival，预计到达时间 对某个运输节点到达时间的预测。Maersk 术语表 必须写清预计到港、到仓还是送达；到港 ETA 不能直接用作本项目预计可售日。
ETD — Estimated Time of Departure，预计离开时间 对货物或运载工具离开指定节点时间的预测。Maersk 船期说明 预计出发不是实际发运；计划调整后应保留新旧时间与来源，不能据计划时间生成完成事实。
AWB — Air Waybill，航空运单 航空货运中承载托运人与承运人运输合同信息的文件。IATA 说明 航空运单、包裹追踪号和采购单号有不同用途；取得运单不表示货物已到仓。
B/L — Bill of Lading，提单 海运中用于记录承运关系等事项的重要运输单据；类型会影响流转和提货安排。美国国际贸易管理局说明 不要把所有提单都理解成可转让凭证；本项目订单发货记录不代替正式海运单证。
POD — Proof of Delivery，交付证明 证明货物交付的记录，可包括签收信息及交付凭证。Maersk 交付证明说明 原ERP负责采购生命周期；平台仅可经审批创建草稿。
HS Code — Harmonized System Code，商品协调制度编码 WCO 建立的国际商品分类体系，国际层级以六位编码识别商品组。WCO 说明 目的地申报可能使用更长的本地编码；不能仅凭商品名称猜码，也不能把编码等同固定税率。
Incoterms® — International Commercial Terms，国际贸易术语规则 ICC 制定的交付规则，用于划分买卖双方的相关任务、成本与风险。ICC 说明 使用时写明术语、约定地点和版本；它不是付款状态，也不能代替完整采购合同。
DDP — Delivered Duty Paid，完税后交货 卖方承担到约定目的地交付及进口清关等责任，通常交付时待卸货。ICC 规则选择说明 是否具备履行目的地义务的条件需另行确认；不要把业务简称“双清包税”直接视为完整 DDP 合同。
DAP — Delivered at Place，目的地交货 卖方负责送到约定地点待卸货，进口清关由买方负责。ICC 规则选择说明 与 DDP 的差别涉及进口责任；只比较运输报价总额容易漏掉责任边界。
FOB — Free On Board，船上交货 适用于海运或内河运输，约定在装运港船上交付，风险在该交付点转移。ICC 规则选择说明 不能因中文常说“离岸价”就把 FOB 套到所有空运、快递或多式联运报价。
商业发票 — Commercial Invoice 列明买卖货物及交易金额、用于商业和通关事项的文件。美国国际贸易管理局说明 它与平台结算报告、买家付款成功回执不是同一种文件；金额和货描应与交易资料对应。
装箱单 — Packing List 说明货物怎样装入各包装，以及件数、重量等内容的单据。美国国际贸易管理局说明 主要回答“箱里装了什么、装多少”，不能替代商业发票；装了多少箱也不等于多少 SKU 件数。
清关 — Customs Clearance 为货物进出境提交所需资料并办理有关手续，直至获得放行的过程。DHL 说明 清关完成不等于仓库收货完成；本项目 P0 不建设报关或税务申报系统。

18.4 财务经营

术语与英文 通俗解释 本项目用法与边界
GMV — Gross Merchandise Value，商品交易总额 衡量一段时间交易规模的金额指标，具体包含项由报告口径决定。Shopify 说明 不同平台对退款、运费和税额处理可能不同；不能把 GMV 直接当到账金额或利润。本项目看板以已定义的指标为准。
AOV — Average Order Value，平均订单金额 同一统计口径下的销售金额除以订单数，用来观察每单规模。Shopify 说明 同期 10 单共 500 美元可得每单 50 美元；必须先说明是否含运费、取消及退款，不能跨口径相除。
COGS — Cost of Goods Sold，已售商品成本 与已经售出商品相对应的成本。Shopify 成本说明 使用FINANCE确认的成本快照，不随当前商品主档改价而重算历史。
经营贡献 — Contribution 标准投影中定义为净销售额减平台费、履约运费和净商品成本。 19.23 USD样例未覆盖全部企业费用，不是会计净利润。
回款划付 — Payout 平台或支付服务把可结算资金划至商户收款账户的动作。Stripe 说明 买家付款、平台结算与银行到账分开；平台不付款。
对账 — Reconciliation 把两组相关记录逐笔匹配，解释金额、费用或时间上的差异。Stripe 对账说明 比较同口径记录，缺少费用不能填零；平台不代替原财务调账。
外汇／汇率 — FX / Foreign Exchange / Exchange Rate 不同货币的兑换及其换算比例。欧洲央行说明 7.000000为验收快照，不是实时牌价；来源汇率不能反用。
RMA — Return Merchandise Authorization，退货授权 批准和跟踪商品退回的安排，通常以授权编号关联原订单。Shopify 说明 原OMS记录授权，WMS记录实收；平台分别观察。
退款 — Refund 将已经支付的全部或部分款项退给付款方。Stripe 说明 只读原OMS成功退款累计；平台不调用支付退款。
实物退货 — Return 把购买的实物退回并进行接收、检验与处置的过程。Shopify 退货说明 由原WMS接收检验；成本转回必须有FINANCE证据。
拒付 — Chargeback 持卡人向发卡机构提出付款争议，由相应争议流程处理。Stripe 争议说明 与主动退款不同，P0不新增办理能力。
净销售额 — Net Sales 本项目使用税外实收（含客户运费）减成功退款累计。 本项目使用税外实收减成功退款；税额拆分不明则报告不完整。
平台费 — Platform Fee 标准投影中用于记录与平台交易相关的费用项目，按约定费用口径保存估算或实际值。 来源估算和实际确认分开；6.57 USD仅为样例。
履约运费 — Fulfillment Shipping Cost 标准投影中指为完成订单配送承担的运费费用项。 买家付4.00是收入、履约付8.00是费用；不混为差额字段。

18.5 系统协同

术语与英文 通俗解释 本项目用法与边界
ERP — Enterprise Resource Planning，企业资源计划系统 把采购、库存、销售、财务等业务信息连接起来的企业管理系统。IBM 说明 既有系统，权威提供商品、供应关系与采购。
OMS — Order Management System，订单管理系统 跟踪和组织订单从进入到履约、售后的业务过程。IBM 说明 既有订单管理系统；用户确认本场景使用OMS。
WMS — Warehouse Management System，仓库管理系统 帮助掌握仓内库存并组织收发与履约作业的系统。Oracle 说明 既有仓库管理系统；权威提供库存与履约事实。
幂等 — Idempotency 同一业务请求重试时，不重复产生已经完成的业务结果。Stripe 说明 同executionKey对应同一外部对象，超时先查回执。
事务发件箱 — Transactional Outbox 把业务变更和待发事件一起可靠保存，再由后台发送事件的方式。AWS 说明 平台执行记录与待发事件同事务；发送仍可能重复，源端仍需幂等。
审计轨迹 — Audit Trail 按时间保留可还原操作经过的记录。NIST 释义 关联分析、证据、审批、执行和回执，不记录密钥与客户明文。

18.6 AI枢纽与数据协同

术语与英文 通俗解释 本项目用法与边界
CRM / 客户关系管理 管理客户互动、服务与协同记录的系统。 读取匿名客户及反馈，经审批创建内部工单，不对客发消息。
ORM / 对象关系映射 程序访问关系数据库的一种技术。 不是订单管理系统OMS的名称。
Pack Size / 订购倍数 采购数量需满足的整数倍数。 与最低起订量MOQ独立。
VOC / 客户之声 客户反馈、意见与体验材料。 主题是线索，不能直接认定已证实产品缺陷。
Cohort / 群组 按共同条件与时间选取的一组对象。 投诉比例须使用相同且已成熟的签收群组。
Connector / 连接器 把来源协议转成标准端口的组件。 定义端口不等于已对接某厂商。
Canonical ID / 统一标识 关联同一业务对象的稳定平台ID。 保留来源编号，禁止跨租户或相似名称自动合并。
Data Lineage / 数据血缘 指标与结论到输入及转换过程的关系。 能追踪来源、版本、时间与计算规则。
asOf / 事实时点 数据内容对应的有效观察时间。 与平台接收时间observedAt不同。
coverageThrough / 覆盖水位 某数据域已完整同步到的时间。 单条最新记录不能证明全域完整。
Snapshot / 分析快照 冻结分析输入、范围与规则版本的记录。 迟到数据生成新分析，不偷偷改历史。
RAG / 检索增强生成 检索相关材料后让模型依据材料回答。 先过滤权限，再检索，最后复核引用。
LLM / 大语言模型 理解和生成语言的模型。 分类、解释与归纳，不替代金额和库存计算。
Evidence / 证据 支持结论的来源记录、指标或知识片段。 不存在或无权访问的引用不得进入回答。
Prompt Injection / 提示注入 外部输入试图改变模型任务或权限。 客服文本和文档不是指令，授权在模型外执行。
Tool Calling / 工具调用 模型提出结构化工具请求，由程序验证执行。 产品模型只有允许的只读工具。
UNKNOWN / 结果未知 无法确定外部动作是否已经生效。 先查询原执行键，不换键重新创建。
RBAC / 角色权限 按角色规定可用操作。 还须租户、环境、店铺和仓库范围过滤。
DEGRADED / 降级 部分能力不可用，只返回已确认的有限结果。 显示RULES_ONLY，不伪称模型解释成功。
累计快照 / Cumulative Snapshot 截至某时点的累计结果。 取最新版本，不将每次抓取值相加。
Outbox租约 / Lease Worker在一段时间内处理某任务的占用权。 租约过期不证明外部动作没发生，SENDING先查回执。
百分点 / Percentage Point 两个百分比直接相减得到的差。 12%到3%的差是9个百分点，不能叫增长9%。

19 最容易混淆的边界

容易混淆 必须分开
平台数据与原系统事实 平台投影是有时间的副本，原系统有权威业务写入责任
ERP库存镜像与WMS库存 指向同一仓货物不能相加；权威来源每域唯一
总量与可售 占用、冻结、不可售不能拿来满足新增订单
计划供给与现货 未来预计入库不能提前计入现货
累计快照与增量明细 前者取最新，后者按唯一事件汇总；必须经适配确认
模型判断与确定性指标 模型解释不替代数字运算和业务授权
投诉率与缺陷率 投诉证据不等于经鉴定的产品缺陷

20 场景判断与核对

场景一：ERP和WMS都显示100件，能不能说有200件

先确认是否同一仓、同一对象、同一时点的镜像。如果是，只有一份权威余额。平台按domain_authority读取WMS库存，ERP镜像可用于核查差异，不能相加。

场景二：平台一分钟前同步成功，补货为什么仍被阻断

同步成功只证明请求处理完成。若库存asOf已超过15分钟，或coverageThrough没有完整覆盖窗口，数据仍旧。需要刷新源数据或核实延迟，不能把observedAt当库存事实时间。

场景三：客户三次催单，是否计三单投诉

投诉工单条数可以是3，但去重投诉订单数是1。分母还需是相同店铺/商品签收群组且观察期结束的订单，不能拿全店所有订单随便除。

场景四：模型说批准采购，能否直接执行

不能。模型没有审批权限，建议必须由另一授权人员确认具体参数与证据。执行器还要核对源条件和有效期。只读分析工具不能调用原系统写端口。

场景五：ERP创建超时，是否再次生成新的executionKey

不能。先用原键查询。可能草稿已存在但响应丢失；换键会绕过幂等并造成重复。查不到也不一定是确定未创建，需要适配器返回权威NOT_FOUND及安全重试保证。

场景六：AI建议采纳后销售增长，是否可以写“AI提升销售20%”

需要可比基线、观察窗及其他影响因素。促销、季节、供给和渠道变化都可能影响结果。P0记录观察值与限制，可以报告关联变化，不能编造已经证明的因果收益。
