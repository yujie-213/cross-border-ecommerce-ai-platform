# B V1.0 原型方向整改版

状态 **REVIEW**，分支 `codex/b-after-sales-v1`，未合 main。前版功能测试通过，但负责人未认可产品体验；本次按确认原型重新组织正式 Vue，最终仍由负责人和星星体验验收。

| 原问题 | 本版处理 |
|---|---|
| 后台功能和表单占据入口 | 四个工作区入口：售后工作台、体验与退货分析、质量风险、知识与资料；工作台主区是待办与 ERP 新到问题，侧区是异常及风险 |
| 读取范围过广 | 与补货共用已核验自建登记清单；当前10款商品、11个店仓关系。商品必须精确身份匹配，订单及工单必须关联登记销售ID；非成员历史列表、直链及风险读取均排除，原记录保留 |
| 案件详情缺少工作顺序 | 客户原话、已核商品/订单事实、AI建议与人工审核三栏；可靠关联直接使用，多商品歧义才选，纠正已有关系留原因 |
| 分析混合多个商品 | 先列本期/上期/变化，再选商品查看主题、原文、实发与实收证据、独立AI解释和行动建议；教学上衣增加27.5个百分点，线缆持平 |
| 调查、风险表单堆叠 | 从商品建议建立调查，自动沿用已选证据，人工记录结论后再登记/确认风险；详情可关闭、撤销并回查历史 |

原始明细、统计说明、模型用量和后台任务折叠；补货算法、采购规则、平台首页、原账号及会话保持。

## 启动与建议体验

双击根目录 `Start-Platform.cmd`，原账号登录，首页进入「智能售后与客户体验」。**本机 http://localhost:5175，API8768**；停止用 `Stop-Platform.cmd`。不要重新初始化或重置密码。

1. **工作台 → ERP 新到问题 → 案件**：默认只显示自建登记范围；核对已有订单与商品关联、事实和缺口。当前真实 ERP 工单存在多商品及诉求不符负例，按事实补证，不包装成质量正例。
2. **体验与退货分析 → 记录来源选“独立教学体验”**：打开最新分析，查看上衣和线缆各自反馈、AI原因及行动建议，再查看原文/退货证据并发起调查。最新报告 `2125240691ee4d0d90dffb0ecb231781`。
3. **质量风险 → 调查 → 人工结论 → 登记/确认**：核实商品及店仓后启用提醒，可关闭或撤销。正式浏览器演示风险已撤销并保留历史；合成 ERP 工程环境已验证原补货单品/批量显示及撤销后消失，未把教学上衣绑定到无关 ERP 商品。

三栏案件“上衣尺码与描述不符”位于独立教学的处理记录中，AI原稿与人工修订均留存。内部处理完成不表示外发回复、退款或 ERP 工单被写入。

## 实测与边界

- 受影响后端/权限及进程测试 **58 PASS / 0 FAIL / 0 SKIP**；前端 **69 PASS**，类型和生产构建 PASS。最后的证据沿用修复已额外运行编译 Vue 三链浏览器 **1 PASS**，含独立Worker恢复及补货提醒。最后仅日期展示调整，类型/构建与实际页面复核通过。具体固定提交及记录见[验证记录](../evidence/B-PROTOTYPE-ALIGNMENT-20261116/validation.json)。
- 正式浏览器实际读到自建范围2条 ERP 工单；现有ERP字段映射沿用已核对结果。本轮**没有完整 ERP 退货总体、没有新真实 ERP 风险绑定正例**。退货对比及本轮AI正例来自明确分开的独立教学数据。
- 官方 DeepSeek 经 A01 **6次 / 11536 Token**，实际费用 **UNKNOWN**，保留 $0.30预约。初稿重复索要已有订单号的问题已修正上下文，真实复测不再要求重复提供；两个商品的分类和解释均可用。旧14次/19502 Token及失败记录另行保留，不清零。
- ERP评价并不证明订单和仓库；未知关联不猜测。发现采用有界20条工单/10条反馈读取，页面标明覆盖边界，不能据此宣称整个清单的全部售后已穷尽。
- 企业正式政策、批次及实物检验证据仍需业务方补齐；ERP商品反馈以单条取证分析为主。AI原因属于调查假设，不能替代统计、身份匹配或人工审批。ERP业务写、采购动作和客户外发均为零。
