# S01 规则决策清单与固定期望

本清单是待操作者提供受控签认记录的输入，不是开发者签认。准入模块只接受与内容摘要、精确 scope、asOf 和有效期绑定的记录。

| 决策项 | 当前引擎可接受的精确语义 | 需要业务记录明确的内容 | 未明确时 |
|---|---|---|---|
| 可用库存 | 输入已是 `NET_AVAILABLE` | 是否已扣冻结/预留；多批次由上游如何形成唯一净额 | 阻断真实准入 |
| 需求 | 逐日显式 `INCREMENTAL_EXCLUDES_RESERVED` | 历史需求转未来需求的方法、版本、适用 SKU/scope | 阻断真实准入 |
| 日内顺序 | 同日供给先入、需求后扣 | 该顺序是否适用于试点仓与预计可售日 | 语义不匹配即拒绝 |
| 欠交 | 负余额累计为 backlog | 是否允许跨日累计、不得把总量充足解释为无中途缺货 | 语义不匹配即拒绝 |
| 日期 | D0 为 asOf UTC 日期，D1 从下一日开始 | 业务时区、预计到货到可售的转换与有效日历 | 阻断真实准入 |
| 供给 | 唯一供给行、剩余未收量、OPEN/RECEIVED/CANCELLED | 采购/送货/入库去重键及状态口径 | 缺失/UNKNOWN 阻断 |
| MOQ/倍数 | 缺口先与 MOQ 取大，再按 orderMultiple 向上取整 | MOQ、箱规、订购倍数区别及当前有效来源 | 缺失阻断候选 |
| 缓冲 | horizon 后继续计算 bufferDays | 缓冲天数及业务依据 | 未签 policy 拒绝 |
| 质量 | `VERIFIED_CLEAR` 才允许候选；`INVESTIGATE` 保留阻断 | 质量结论来源、负责人、版本、时点 | AI 不得解除 |
| 其他约束 | 仅 `REVIEWED_NOT_APPLICABLE` | 确认当前 scope 没有遗漏硬约束 | 未审查不得写不适用 |

固定离线期望：库存 10，D1/D2 需求 8/8，D1 已有供给 2，基线 D1 余额 4、D2 余额 -4；总缺口 4，MOQ/倍数均为 5 时候选 5，候选后 D2 余额 1。该样例仅验证现有固定引擎语义；负责人需用真实业务依据另行签认，不能复制样例批准人或引用作为正式记录。
