# 自有商品补货分析使用说明

适用负责人于2026-11-15实际体验通过的main产品版；任务与验收状态以TASKS为准。旧V2全目录手册及旧截图保留历史。

1. 双击仓库根目录 `Start-Platform.cmd`，使用本机 `admin` 密码登录。当前Alienware默认 http://localhost:5173、API8765，以启动器显示为准。停止使用 `Stop-Platform.cmd`，保留数据库、分析历史和请购记录。
2. 平台首页进入「智能补货」。工作区按优先级发现需关注商品；「检查自有商品」只联网读取登记范围最新事实，批量零模型、零采购写，历史批次不会重算。
3. 从风险队列进入「商品分析」，按SKU、判断或店仓筛选。打开商品先看各仓结论，切换仓库后AI、证据与采购条件一起切换；各仓计划合计不是可调拨库存池。
4. 点击右上角「更新补货分析」，重读当前店仓并自动生成AI建议。生成中显示实际状态，失败保留已有补货结果并显示原因和重试；AI区可单独更新建议。缺报价等采购条件不阻止分析和AI；日常AI不设平台累计次数/Token/金额上限，服务商余额、超时和防重复约束仍有效。
5. 查看AI行动建议，再看销量、补货前后曲线和ERP比较。「采购数量」默认采购候选，缺候选时使用参考量；修改数量后填写原因。「到货日期」默认引用报告报价交期，可调整、恢复；缺交期时自行填写。两项联动曲线，保留到货前缺口。日期仅参与当前报告试算，不代表ERP确认在途或供应商承诺；窗口外日期会明确提示。
6. 人工核对供应商、报价、MOQ/整箱、已有采购和来源限制，勾选后点击「确认并提交」。必要条件缺失只限制采购提交，不隐藏分析。平台人工确认不等于ERP领导审批，不自动审批、下单、收货或入库；结果不确定时只用原命令核对，不重复提交。
7. 「请购管理」按登记商品所在仓库有界发现并核对ERP单号，逐单回读当前状态；页面打开、手动刷新及可见页面每60秒更新。待审核橙色、待下单蓝色。读取失败会说明旧状态，搜索超限会说明不完整，不据此推断没有单据；不是全ERP台账或实时推送。

当前登记教学范围10款商品、11个店仓对象，线缆含东/西双仓。只读取登记核验salesIds，不扫描共享全量历史；新增订单、商品或仓库需先登记核验，不能仅凭SKU前缀获得权限。新电脑以独立空库和恢复核验的登记范围运行，旧电脑本地分析/请购历史未迁移。

ERP未提供建议显示“ERP未提供”，不等于建议数量为零。未知日不补零，样本稀疏、陈旧、未知库存及交期按实际限制显示；未知可售日期的采购不抵扣。曲线基于打开报告的观测时间与预测窗口，旧报告不自动重写；需要最新事实时主动更新分析。

取消或失败保留已完成结果，不能当完整分析；成员或来源权限变化阻断。教学产品体验通过不代表企业数据、规则、ERP安全和AI正式用途四门已验收。
