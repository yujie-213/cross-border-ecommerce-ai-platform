# 全项目 ERP 教学仿真数据规范

版本：v1，2026-11-13。适用全部业务 Agent、导入工具、验证脚本和人工协作流程。负责人本轮明确确定的统一要求在此整合；具体任务和执行许可仍以 [TASKS](../TASKS.md) 为准，本文不授予任何业务写权限。

## 权威与来源

ERP 是业务实体、单据、状态、库存和流水的权威来源；Git 保存契约、计划、非敏感证据摘要和审计定位。中台的预测、建议、解释及人工复核是各自来源的派生结果，不能覆盖 ERP 事实。

通过真实教学 ERP API 形成的经营记录标记 `SIMULATED_BUSINESS_DATA_IN_TEACHING_ERP`。它们是教学环境中真实执行的仿真经营事实，不等同现实交易、企业生产数据或企业验收。离线 Fixture/Mock 标记 `SIMULATED_ENGINEERING`，不得写成 ERP 实测。真实 API 请求失败时不得切换 Mock 并宣称成功。

## 创建、变更和业务状态机

1. 只通过获准的正式 ERP API 创建和变更仿真数据；禁止直连 ERP 数据库、SQL 改值、伪造审批、收货累计或库存状态。
2. 先核对当前契约、合法主体、精确对象/归属和副作用，再依 ERP 状态机逐步执行。采购申请、领导决定、正式下单、送货、收货、质检、库存确认和付款分别控制，不互相替代。
3. 不因有管理员技术权限而代签领导决定；不可逆决定、外部交易、付款/外部通知及其他任务限制按当次明确授权执行。禁止未经授权修改他人数据。
4. 不为迎合 AI 预测或测试期望倒改真实业务记录。数量、单价、币种、金额、时间、累计、库存余额和流水必须一致；业务不支持或规则缺失如实阻断，不能通过编辑派生字段制造通过。
5. 历史业务时间、实际创建/过账时间分别保留。仿真历史订单不冒充过去实际过账；任何初始库存/历史重建均须有获准来源和对账依据。

## 归属、回读与恢复

每批记录保存 datasetId、importBatchId、范围版本、真实租户/店铺/仓库/商品/单据/明细 ID、父子关系、来源、操作者和审计。SKU 或名称前缀只是辅助标识，不能证明所有权或隔离。普通监控沿 [自建范围契约](../contracts/s01/owned-dataset-scope.md)；其他人员在同范围 ERP 中新增的采购，应通过获准的关系发现/核验机制纳入上下文，不能仅因不在旧 purchaseIds 清单中而忽略，也不能因此扩大 SKU 监控范围。该发现机制尚待实现，不由本文宣称已有能力。

每次写入后必须独立只读回读实际单据及受影响的状态、关系、库存和流水。写入回执、HTTP 200、批量 `code=0` 均不足以证明业务成功；检查逐项失败、复用标志、数量及唯一流水。失败或不完整保留原始证据，不能按零值继续。

发送结果 UNKNOWN 时，先用原业务键/原单据/原幂等标识查询核对；禁止换键盲重发。只有当前契约明确允许且可证明安全时才有限重试。低频有界读取、分页完整性/去重/状态漂移检查沿用既有 D01/D03/O01 约束；多接口非原子必须披露。

## 证据、隔离与规模

公开材料不含 Key、Token、Secret、密码、会话凭据或未经授权的第三方资料。普通教学数据公开授权按当前任务适用，原始响应默认留在 Git 忽略私有目录；摘要保留请求时间、方法/接口、状态、最小关键字段、真实 ID、文件指纹和定位。不保存认证响应或认证请求正文。

账号/租户/行级隔离必须有 ERP 证据，应用清单、标签和共享管理员不构成源端独占保证。未登记监控对象默认排除；异常归属不自动接纳。每轮只创建当次获准规模，不从 2SKU 自动扩至 8/30SKU，不另建通用数据管理平台。

## 与既有决定的关系

整合 [DECISIONS](../DECISIONS.md) 的 ADR-S01-MONITOR-006、PILOT-007、MVP-008、MVP-009 及本轮采购调查决定；历史失败、旧预算和停止点按各自时点保留，最新明确授权覆盖冲突范围。D01 继续只读，D02 管映射，D03 唯一快照，D04 定位，G02 审计，B01/B02 保持权威计算分工。未来合法写入采用另行评审的明确边界，不向只读 Agent 注册任意写工具。
