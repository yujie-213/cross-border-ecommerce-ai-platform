# S01 V2 工作台运行与操作手册

适用当前独立V2评审分支。任务状态只读[TASKS](../TASKS.md)，契约见[V2接口与业务冻结](../contracts/s01/v2-full-replenishment.md)。这是教学隔离环境运行方式，不能据此开放企业生产采购。

## 安装、配置与增量迁移

使用Python3.13及项目锁文件；已有可用环境不重复安装。前端沿现有Node/npm环境。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e . --no-deps --no-build-isolation
$env:COMMERCE_MODEL_PROVIDER='mock'
$env:COMMERCE_MODEL_NETWORK_ENABLED='false'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

只允许本机`.env`获准隔离库`s01_a01_test_20261112`；不要换库或绕过迁移目标检查。0009增加D01采集检查点和逐对象结果，0010增加D03清单；原0001—0008不改，当前唯一head为0010_s01_v2_manifests。升级和重复升级已测，不做降级/删表。启动不隐式建表或迁移。

ERP凭据仅本机`.env.erp`，固定已有HTTPS教学Connector/局部证书例外/禁重定向；不输出或提交密码、Key、Token、Cookie。源租户本轮明确为1；业务授权为当前可读店仓SKU的全部只读分析。实际ERP行权限优先，管理员权限不赋予采购权。企业业务门保持BLOCKED。

## 启动独立API、Worker和前端

根目录运行：

```powershell
.\.venv\Scripts\python.exe tools/s01_v2_dev.py --execute-local --duration 1800
```

默认模型和采购关闭，启动不访问ERP。工具创建本机短期可信测试身份并启动独立API与单个Worker；私有会话在Git忽略的`data/private/s01-v2-local/session.json`，包含短期凭据，不要截图或公开。它是教学开发入口，不能用于生产身份签发。另一个PowerShell终端启动前端：

```powershell
$taskSession=Get-Content data/private/s01-v2-local/session.json -Raw | ConvertFrom-Json
$env:S01_API_TARGET=$taskSession.apiTarget
Set-Location frontend
npm ci
npm run dev
```

打开`http://localhost:5173`，连接可信短期身份。页面显示“全量补货工作台”。仅在另有明确模型/教学写入授权时给启动命令增加`--enable-model --enable-requisition`。当前验证授权独立计数：最多4次/96000Token/$0.20，单task1次/24000Token/$0.05预约；费用未知不释放为零。普通浏览、详情和批量始终不调用模型。

## 使用流程

1. 点击“分析全部SKU”。目录采集完成前不显示伪造发现总数；之后显示不同SKU数、店仓对象数、各终态与覆盖率。SKU同名不同店仓不会合并。
2. 用商品/SKU、店铺、仓库、来源、分析状态、风险组筛选整个结果集。列表每页50，不是只分析首50条。没有Listing、归属不明、缺少事实的对象也保留。
3. 打开详情查看来源、原始建议、库存、正式采购、有效报价、MOQ/整箱及未知事项。规则风险、ERP源紧急度与未知优先级分组排序，没有统一虚构分数。多库存记录不自动相加；ERP0不表示无需补货。
4. 主动点击“新建单品分析”才重新读取当前事实并请求A01解释。历史和查看详情不产生新调用；模型失败保留确定性结果。历史可再次打开，不自动重算。
5. 有明确采购权限且处于获准自有教学范围，必要约束通过时开放人工确认。REFERENCE_ONLY/算法UNKNOWN本身不禁购；有效报价、业务关系、库存冲突、正式采购查询完整性、正数量、MOQ/整箱仍校验。原建议与最终量分别留存；改量必填原因。
6. 勾选理解来源及未验证事项后提交。中台只创建采购草稿并submit，成功显示“待领导审批”，不代替审批，不下单/收货/入库。共享样本只读，不能因为可分析就提交采购。

## 中断、失败与恢复

每页采集和每个结果持久化，原task请求预算先扣后发送。Worker崩溃后由租约恢复同一task，沿原期限/模型和ERP请求预算；内容指纹或源身份/权限变化则阻断。任务内采集不是跨任务缓存。

点击取消后已完成结果保留，剩余显示未完成；“重新检查全部SKU”显式创建新task，旧结果和预算不被覆盖。全局认证/权限失败、分页漂移/不完整、503、超时、请求耗尽会显示限制，不能当成0补货。

请购显示原命令待确认时，先“使用原命令核对”，不要换键盲发。保存状态为UNKNOWN/PREPARING时沿原操作继续；SUBMITTED读取同一ERP号。网络等待最多90秒，超时不证明未创建。ERP发送不确定先查原业务号；当前状态机没有第二次创建权限。页面刷新/服务重启仍可从单品历史恢复。

仅本轮开发工具支持在私有`control.json`写入`{"status":"REQUESTED","action":"restart"}`重启自己的API/Worker，身份保持不变，API端口可能改变；前端须用新session.apiTarget重启Vite。`stop`仅关闭该工具拥有的进程。正常到期也自动关闭，不能强杀未知服务。

## 完整验证

```powershell
$env:COMMERCE_RUN_MYSQL_TESTS='1'
$env:COMMERCE_MODEL_PROVIDER='mock'
$env:COMMERCE_MODEL_NETWORK_ENABLED='false'
python -m pytest tests --basetemp=.tmp/v2-review-fresh --junitxml=.tmp/v2-review.xml
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
python docs/planning/build_docs.py
python docs/planning/check_plan.py
```

使用新的可写basetemp，避免Windows受限目录残留影响结果。浏览器用既有Edge：`npm --prefix frontend run test:browser`；真实用例默认跳过。V2_FULL_BROWSER只在明确授权且尚无live-operation.json时运行，因为它会创建并submit一张自有教学申请；已有回执必须使用V2_RECOVERY_BROWSER，不可为了重跑另建一张。V2_FINAL_BROWSER会创建只读批量及一次明确单品模型任务，已有fallback-single-task.json时也拒绝盲重发。测试代码中的完整环境变量名为`S01_V2_FULL_BROWSER`、`S01_V2_RECOVERY_BROWSER`、`S01_V2_FINAL_BROWSER`，仅设置本次需要的一项并配合`--grep`。

`python tools/verify_s01_v2.py`只读取隔离MySQL与已有私有采集，独立核对响应SHA256、来源SKU全集/结果集、实际模型尝试/用量、请求方法和预算，生成公开白名单投影`docs/evidence/S01-V2/live-audit.json`，不发送ERP或模型请求。需要先有对应真实测试生成的私有任务引用；没有引用不会冒称实测成功。

原始响应、会话、模型请求和完整业务报告只在Git忽略私有目录。公开仅提交教学授权下的字段投影、请求指纹和不含凭据的截图。本轮完成停在REVIEW，未经负责人验收不合main。
