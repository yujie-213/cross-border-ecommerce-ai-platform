# 自建数据集的统一监控范围契约（评审稿）

只监控本项目经授权创建、登记且独立ERP回读/关联验证通过的数据。本文是普通工程设计，不含现有ERP资源、连接、凭据、Provider记录或完整业务数据。

## 范围的权威来源

D02管理Dataset、ImportBatch、MonitoredMember及不可变ScopeVersion。成员持有真实ERP租户、商品、店铺、仓库、Listing和单据/明细关系；商品名称和SKU前缀只用于展示或辅助查重，不能证明归属。G01决定当前主体可使用的动作/字段/范围；D02范围与G01授权必须同时满足。

状态为PLANNED、IMPORTING、READBACK_PENDING、VALIDATED、ACTIVE；异常QUARANTINED，退出RETIRED。新资源先登记回执，再独立GET核实真实ID与关联，全部必要验证完成后才能发布新的范围版本。负例成员可以身份有效、业务质量阻断；成员归属不等于业务准入。

## 所有入口必须一致

- 普通查询、单SKU分析、未来批量任务和统计统一解析datasetId/scopeVersion及当前G01权限；未登记对象默认排除，不展开任意店×仓×SKU组合。
- 任务固定受理时的成员与范围版本；执行前复核当前撤权/停用，新版本新增对象不扩入旧任务。
- 每个新分析仍从正式ERP API获取本次事实并固定到D03快照；监控清单不是库存/销量答案缓存。
- 集合读取只接纳精确登记ID及可证明的父子关系；重复、漂移、外来记录、未登记依赖或覆盖不完整明确阻断，不静默填零或全库扫描。
- 历史报告保存当时范围/快照并检查当前读取权限；统计使用同一范围版本和明确去重口径。
- 监控清单可配置和扩展，不把某个SKU数量硬编码为业务规则。未来批量分析复用现有O01预算、期限、幂等和租约，不建设第二运行平台。

## 安全和证据

应用范围控制不能保证ERP侧其他账号无法修改记录。独立账号/租户或源端行级范围须有实际证据；前缀、标签和共享管理员权限都不是独占保障。每次采集检查身份/关联/源版本，异常隔离，保留跨接口非原子限制。

G02记录审计，D04定位证据，D03唯一拥有manifest，B01唯一负责指标，B02负责情景与候选，A01只解释获准事实。所有真实身份、请求/响应及授权信息按本机受控留存策略保存，不默认公开。

本契约尚未实施，不证明已有ACTIVE监控清单或业务验收通过。
