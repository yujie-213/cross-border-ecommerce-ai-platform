# 简洁协作补充约定

本文件不重新定义任务状态；唯一状态/转换/验收规则在[TASKS](TASKS.md)。不保存另一份可修改任务表或完成率。旧详细协议已保全在[归档](archive/plan96-v0.1/README.md)，不作为当前开工门槛。

## 开始和并行

按AGENTS→HANDOFF→当前任务/直接依赖→相关契约增量读取。先核对实际branch/HEAD/dirty，不把交接中的“观察时HEAD”当永远不变的当前HEAD。没有下一条任务授权时，只报告候选而不自动开工。

同文件一名写入者；公共契约/迁移/组合根/锁文件/台账串行合入。并行须接口已冻结、实际文件不相交且资源允许；合并后跑受影响契约/集成回归。未知他人修改先保全归属，不以ours/theirs或重置覆盖。

## 提交和证据

实现提交C1固定后，针对其真实运行测试；保存命令、环境/样本版本、模拟或真实类别、退出码和原始结果。随后提交证据/台账/交接C2。若C2改了相关实现/fixture/契约/配置，重测新实现commit。验收记录引用实际实现和证据commit，不在文件里要求填其自身尚不存在的SHA。

本轮整理/建仓不是业务开发；SETUP-001可交付REVIEW，不伪造独立验收。首次提交后用后续本地文档提交记录初始SHA；交付时最新HEAD由Git读取，避免自引用循环。任何本地提交不代表获准push或发布。

真实敏感数据不因“Git事实源”而全量入库；Git保存许可允许的最小引用/版本/指纹和验收材料。真实接口、动作、模型、容量与业务收益各自需要适用证据，不能拿文档渲染/Mock代替。

## 中断和恢复

- 已提交：核对基点到HEAD及当前dirty，读失败/未完成测试，继续原任务。
- 未提交：记录WIP文件/归属/指纹、做成与未做事项，能按授权提交则留下WIP提交，不能则明确WORKTREE_ONLY；不得声称已验收。
- 测试失败/环境缺失：保存FAIL或NOT_RUN和解除条件；不靠删测试变PASS。
- 交接不完整：从实际Git与文件重建最小事实，未知项标待确认；不得为了重做而覆盖用户修改。
- 历史证据失效：保留原记录，开缺陷/重开评审，针对新版本补回归；旧PASS不覆盖新代码。

完整CI平台不在本轮建设；当前文档工具只生成/校验计划、任务DAG、归档映射与静态阅读版。
