## 1. 先看需要决定什么

“契约”就是模块之间对输入、输出、责任和失败行为的约定。例如前端拿到 `null`，必须知道它表示未知，不能显示成库存为零。先约定，再实现，才能避免不同 AI 或模块各算一套。

已经明确的原则直接沿用：单 SKU、教学 ERP 只读＋获准受控补充、必要质量门禁、真实 A01 解释必做、当前不开放采购确认/审批/执行。API 与 Worker 独立进程；B01 唯一计算；所有模型经 A01；D03 唯一 manifest；缓存 OFF。无需重新决定这些原则。

建议负责人按 §2 的 R01—R12 分别回复“同意范围＋保留项”或修改意见。R 编号只是本文评审定位，不是新任务或新验收编号。签认须绑定被审 Git 提交、具体小节和保留条件；不因某一项同意而把整份专项设计或 A-01 自动验收。

来源枚举的候选值：environment=TEACHING_ERP/CONTROLLED_INPUT/ENGINEERING_FIXTURE；acquisitionMethod=NETWORK_READ/CONTROLLED_FILE/GENERATED_FIXTURE；nature=OBSERVED_FACT/CONTROLLED_FACT/HYPOTHESIS。仅是当前 S01 草案，不定义全平台来源分类；三轴组合必须与实际证据一致，不能仅靠枚举证明真实性。

## 5. 状态、取消与错误（R09）

O01 Task State 原样保持 QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED；I01 仍为 PENDING/LEASED/RETRY_WAIT/DONE/DEAD/CANCELLED；报告完整性沿用 COMPLETE/PARTIAL/RULES_ONLY/BLOCKED。AI 展示状态候选为 AVAILABLE/UNAVAILABLE/INVALID/NOT_ATTEMPTED。最后一组不扩展前三组。

| 具体情形 | 候选输出约束 | 不能误解成什么 |
|---|---|---|
| 正常发布明确的业务阻断报告 | task=SUCCEEDED，report.completeness=BLOCKED，保留缺项/来源，AI 状态独立 | 系统完成处理不表示该 SKU 可采购 |
| required 质量缺失但供需事实可信 | 可保留可信事实，采购适用性阻断；不能仅 RULES_ONLY 掩盖 required 缺口 | AI 成功不能消除阻断 |
| 规则合法、AI 超时 | AI=UNAVAILABLE、内容为空、提示“AI 解释不可用”；报告完整性按已签矩阵 | 不是假 SUCCESS，也不自动让整个规则结果失败 |
| Schema/引用/事实保持失败 | AI=INVALID，丢弃解释，保留合法规则结果及原限制 | Schema 合法不代表业务语义可信 |
| 未合法调用 | AI=NOT_ATTEMPTED、内容为空，原因可见 | 不填伪造 providerRequestId/模型版本 |
| 排队/运行中取消、旧 lease/plan、超期、撤权 | 安全点停止新步骤；条件提交拒绝迟到结果；未发布不出现 reportRef | cancel 受理不是撤回已发网络请求或清零费用 |

最终 COMPLETE/PARTIAL/RULES_ONLY 的业务组合须由 RULE 签认；上表不替代该矩阵。首版只用 FINAL Workflow；YIELD 不发布，也不要求本轮建设等待恢复设施。

HTTP 错误保留 `{code,message,details,traceId,retryable}`。401 未认证、403 拒绝动作、资源不存在/越权读统一404、409 幂等内容或版本/状态冲突、422 参数错误；未实现能力明确拒绝。内部错误沿 AI §3.4，messageSafe 映射为 message；detailsRef 不直接展开敏感内容。retryable=true 仍须满足原预算/deadline/当前权限，不授权 SDK 隐藏重试。异步受理后的错误由任务查询表达，不能用202冒充业务成功。

## 6. A01 与 S01 解释（R11）

公共 ModelRequest 完整沿 [AI §9.1](../../agents/AI_DETAILED_DESIGN.md)，不维护另一个版本。必填字段为 schemaVersion="0.2"、logicalCallId/attemptId、taskRef/queryRef、planVersion/participantId/snapshotId、principalRef/policyContextRef、purpose、deploymentRef、promptRef、contextBundleRef、outputSchemaRef、requiredCapabilities、toolSpecRefs、parametersRef、allowanceRef、deadline、cachePolicyRef、traceId/parentSpanId。正式 S01 调用 taskRef 非空、queryRef=null，三项 plan/participant/snapshot 非空；toolSpecRefs=[]，缓存策略内容 OFF。

不接受 parameters/deadlineRef/toolSpecs/toolSpecsDigest 或自由 messages 别名。A01 解析引用、授权/许可、能力/用途与剩余期限后，才生成内部 ProviderRequest：payload={modelRevision,messages,parameters,outputSchema,toolSpecs}；control 保存原 attempt/许可/deadline/timeout/关联及服务端摘要。控制信息不直接拼入模型正文。

S01 拥有 Prompt/Context/用途 Schema；Context 只含已计算 B01/B02 产物、合法证据、假设/缺项及信任/敏感度，原始外部文本只能当数据。A01 负责技术/结构校验，S01 负责事实和引用支持，O01 负责最终发布；本轮不实现三者。

| 输出字段 | 草案字段规则与意义 |
|---|---|
| recommendationReasons | 必需数组，1—8 项；说明已评价候选或先补证/调查原因 |
| keyEvidence | 必需数组，1—8 项；只引用当前 Context 支持项 |
| majorRisks | 必需数组，0—8 项；存在必需风险时语义门禁禁止遗漏；空不表示已证明安全 |
| humanConfirmations | 必需数组，0—8 项；待人工核实事项，不能声称已批准 |

每项仅 `{text,supportRefs}`；text 非空、最多500字；supportRefs 1—8个当前白名单 DataRef，禁止额外字段/任意URL/SQL、权威数量/日期或审批字段。风险为空只有在签认金标准允许且无必需风险时才可能通过；不能让模型自己决定放宽限制。结构边界是工程草案值，预算/模型输出能力仍需另验。

正例：引用固定 gapRef 解释“缺少质量证据，先补证”；反例：同一 gapRef 却说“质量安全，可批准采购”，即使结构合法也必须弃用。数值、日期、单位、约束与质量结论不得被改写。已知事实一致性可以规则校验；主张支持、风险完整性与人工边界仍须许可金标准/人工评审，文档自检不能证明模型效果。

调用只预留一次原 task attempt，SDK 不隐藏重试；usage 未知保留占额。模型成功、失败、未发送、发送后结果不可得分别记录。完整 MVP 仍必须有 C-04 的真实成功/降级及 UI 证据；Mock 只用于工程联调。
