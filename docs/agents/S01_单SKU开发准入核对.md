# S01 单 SKU 最小开发准入核对与建议

版本：0.1 · 2026-11-11 · 核对基点：`42a941790b4611c391ee1b8f659d3d969ef8b856`。仅证据复核与建议，待负责人评审；不是开发授权或开发 TODO。

## 1. 结论与单 SKU 范围

**当前尚不具备产出该 SKU 可采购候选的业务数据与规则准入条件。** 推荐保留“教学 ERP 只读接入＋单 SKU 获准受控补充”的路径；先签认下列三项决定，实际补齐并核对必要输入与规则后，再评审相应开发范围。不能把“接口可读”或“同意补充”写成数据已经就绪。

本表的 **SKU-A** 仅指既有调查 R2-V01 发现、R2-V04 精确商品查询检查通过的同一个样本 SKU，是阅读别名，不是新建商品或已冻结 canonicalSkuId。既有证据未保存原始 SKU、店/仓 ID 和数量，本轮不能还原这些值；“一个获准 SKU”仍需负责人以受控登记绑定到确切身份。沿用此前一个仓库、一个独立选取店铺的观察，不换 SKU、不扩大范围。店铺与该库存的归属关系尚未证明，采购、入库和订单样本也不能一律当成 SKU-A 的记录。

本轮新增 ERP/认证/模型调用均为 **0**，未重放历史请求。原调查的关闭 TLS 校验授权只说明历史过程，本轮不沿用它发送新请求；任何新认证、关闭 TLS 校验或业务写入均须另获明确授权，写入也不属于当前 S01 只读范围。

依据：[MVP 实施文档 v0.2](S01_MVP实施文档.md) §3.4—3.5、§5—6、§14；[ERP 调查报告](S01_ERP接口调查与字段映射.md) §2—6；[原 S01 专项设计](S01_补货Agent专项详细设计.md) §4、§10；[脱敏实测记录](evidence/s01-erp-survey-20261111.json) `liveVerification.businessObservations`。下文 R2-Vxx 均可在该数组按 id 定位。原专项“可选 A01”已由 [ADR-S01-AI-001](../DECISIONS.md) 和 MVP v0.2 覆盖，其他业务规则不变。

## 2. 八项准入核对表

“已验证”只表示调查当时的字段/返回观察，不表示当前数值、完整性、时效或业务规则已通过。以下八项均仍有准入缺口；不会把未知值、空列表或请求失败补成 0。

## 3. 最少需要负责人决定的三件事

以下均是**推荐方案，尚未批准**。负责人可以一次评审答复三项；实际数值、标识与敏感附件通过受控位置提供，不写聊天、Git 或本文。决定处理路径与提供可用数据是两件事，后者未完成时缺口继续存在。

| 决策 | 推荐方案及必须明确的内容 | 对 MVP 的影响／未决定时的结果 |
|---|---|---|
| D1：哪一组身份作为唯一试点？ | 继续用上述 SKU-A，不另选样本。指定能定位原样本的受控引用和核对人，签认 tenant、店、仓、SKU/店铺 SKU、单位与仓用途；明确独占或共享库存使用范围。若负责人已无法定位原样本，先保留“身份未绑定”，不凭现有 JSON 猜值，也不自动另查 SKU | 决定哪些库存、订单、供给能合并。未完成则停在身份/数据阻断说明，不能称为一个已绑定 SKU 的完整分析 |
| D2：是否采用“教学 ERP＋有依据的单 SKU 补充包”？ | 推荐采用，由负责人指定数据/采购核对人。只补表中缺口：库存观测、覆盖完整的销量、逐行供给与可售日、MOQ/独立倍数及适用硬约束；同时签认一份本 SKU 计算口径：库存净额/分桶、历史窗口/订单状态/时区、未来需求策略及预留关系、业务日/同日先后/缓冲端点、供给状态/去重、交期与候选比较依据。不代填任何数字或规则 | 补齐并评审后可支持单 SKU 确定性基线/候选，结果标明各域来自教学源或受控补充，不能称生产 ERP 验收。若只认可显式需求/日期情景，则仅能交付相应假设下的情景分析，不能算历史需求链或真实供应承诺已通过；拒绝补充则现有证据不足以完成核心闭环 |
| D3：质量缺证时是否保留采购阻断？ | 推荐保留必需质量门禁；指定质量核对人，提供该 SKU 合法替代信号/质量结论及其证据、适用范围、有效期和调查规则。无依据就保持缺失，不把 required 改 optional；已有调查触发则先调查，不凭人工一句“通过”覆盖证据要求 | 数据与规则齐全时可展示供需风险；质量仍不足则只能发布带采购阻断的受限结果。完整可采购候选验收必须满足已签认质量门禁，A01解释成功也不能解除阻断 |

推荐一次提交一个**窄受控包**，无需建立完整模拟系统：一条试点身份登记＋适用的八域输入/完整性声明＋一份本 SKU 规则配置与质量策略。各域至少记录负责人、原始出处/证据定位、观测或业务截止时点、单位/时区、范围/覆盖、有效期与版本；并记录读取环境、读取方式、事实/情景性质。未知、缺失、无适用值和经证明的零值分别表达；“无供给/无销量”需范围与覆盖依据。签认文件只是输入依据，不替代 B01/B02评价或创建真实采购批准。
