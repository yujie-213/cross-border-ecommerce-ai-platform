# B V1.0 产品体验整改

状态 **REVIEW**；分支 `codex/b-after-sales-v1`，固定被测实现 `49808a0d95c472ff908ddc37d162147e7346ec20`，接手基点 `511112be43afbe403bae3b181d05252f1823ba1c`。本轮修复按业务流程组织正式产品，原型方向确认仍有效，最终验收由负责人和星星完成。未合 main。

## 主要变化

| 原产品问题 | 现在的处理方式 |
|---|---|
| 以新建表单和后端功能为入口 | 工单、商品评价、订单反馈直接进入处理；已接入案件按待办、状态、来源和商品查找，人工补充及教学入口降为次要操作 |
| 可靠关联仍要求人工输入，评价相关编号可能被误当订单 | 服务端重新取证；评价按唯一租户商品及准确 SKU 自动关联，订单反馈按真实 order_id 独立核对，多商品才选明细；related_id/no 不推断为订单，首次确认无强制理由，纠正已有关系留痕 |
| 原始 JSON、窗口配置、主题代码占据日常页面 | 商品/证据/AI/人工审核双栏；日期范围使用已核资料，主题用多选，教学绑定选择商品及独立核验后的 ERP 店仓；技术凭据折叠 |
| AI 与事实和调查脱节 | 真实模型分类、政策草稿、基于反馈原文及主题的原因解释；草稿可带入人工审核，原因可转调查。无政策和无证据时明确降级，失败保留事实和部分结果 |
| 异常难理解、风险像独立技术系统 | 显示本期、上期及百分点变化，异常商品优先，反馈筛选到商品；调查→疑似→人工确认→补货提醒，撤销/关闭/到期保留历史，未知仓库不能生成有效 ERP 风险 |
| 售后与平台脱节 | 复用原登录、导航、页面、StatusBadge、任务及持久用量；首页保留多 Agent 入口，近期任务含售后；原补货算法和采购规则未改 |

另修复真实已有环境中“教学资料停用后无法重新启用”。重新启用仍要求封存和独立回读指纹一致，不覆盖资料。

## 启动和三条体验路径

双击根目录 `Start-Platform.cmd`，使用原 admin 登录。**本机 http://localhost:5175，API8768**，首页进入「智能售后与客户体验」。新机器按 README 初始化；不要重置原账号。停止使用 `Stop-Platform.cmd`。

1. **售后处理**：从 ERP 工单/评价打开问题，查看自动关联及未知项→核实事实/政策→AI→人工审核→查看历史。当前可查看“上衣尺码描述核实 · 产品整改体验”教学案例（切“内部处理完成”或“全部历史”）；实际 AI 草稿已人工采纳并持久保存。
2. **客户体验**：先看 ERP 评价并打开商品问题；退货对比进入独立教学资料最新报告，查看上衣 `2.5% → 30%`、**上升27.5个百分点**，筛选商品反馈→查看真实 AI 分析→选证据调查。最新报告 `e7c3eb78133e43d0a8e85094f29fb563`，旧报告保留。
3. **质量协作**：从调查补充证据→记录人工结论→登记疑似→人工确认→核对来源、商品、店仓和有效期。独立工程环境已验证补货单品/批量提醒及撤销消失；本机本次教学风险已撤销，可在历史查看。真正 ERP 提醒仍需负责人确认适当教学商品映射并通过独立回读，不能把任意同名商品或未核仓纳入。

## 真实数据与模型验证

已通过获准只读 ERP 实际核对 customer-tickets、customer-voice 的 reviews/feedback、订单及商品字段。正式浏览器打开评价后自动关联唯一商品，不要求重复确认。读取每次有界10条反馈/20条工单，显示时间及覆盖边界；不宣称全量覆盖。评价不证明订单或发货仓，工单标题不证明完整会话。

用户本轮明确允许模型，B 使用独立授权配置，经 A01 调用官方 DeepSeek：**14次、19502 Token、实际费用 UNKNOWN，保留 $0.70 预约**。11份输出通过本地业务校验，3份未通过，不能把任务完成等同于全部 AI 输出可用。最终正例包括真实 ERP 评价主题/解释、教学政策草稿及人工采纳、教学反馈分类和有原文依据的原因分析。

先前两次解释引用不合规、一次草稿复述退款状态，分别保留失败/降级历史；已收紧动态引用枚举及输出要求，域校验失败现在返回不可用部分结果，不丢已核事实、主题和用量。模型仍可能失败；无有效政策的真实 ERP 案件不会套用教学政策。Provider 原文、ERP 原始响应及私有配置不公开。
