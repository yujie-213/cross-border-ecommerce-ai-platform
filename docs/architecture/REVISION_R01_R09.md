## 02 核心差异

| 维度 | 修订前 | 修订后 |
|---|---|---|
| 业务执行入口 | O01与场景两条路径并存 | 统一由O01调度场景执行；联合报告步骤单独标注 |
| 计算实现 | 逐日指标与情景模拟边界模糊 | B01是唯一指标评价；B02组织/预测/求解并引用评价 |
| 降级决策 | 技术错误携带业务RULES_ONLY结论 | 技术错误、领域限制和整体报告业务状态分别管理 |
| 分析上下文 | 单scenarioId | participants + SINGLE/JOINT；计划、数据和预算有版本引用 |
| 快照/证据/报告 | 可能重复保存同一内容 | 固定输入清单、证据定位、任务报告三种归属，其他模块持引用 |
| 任务限制 | 两域/一次的固定限制 | 默认2/1，受策略约束的有效配置；可分批，不无限循环 |
| 流程结束条件 | 报告后建议/审批/执行容易被理解为自动连续发生 | 四种独立流程终点，候选方案不等于建议实体、批准或执行 |
| 基础设施契约 | 提前列出全面技术抽象 | 按已知需求保留必要边界，不由接口清单反推部署 |

需求文档第5.2节及架构文档第11.1节的22项产品覆盖表与修订前逐字一致；场景、模块编号及各业务分期均保留。本次没有把完整中台改为补货专用MVP，也没有为压缩数量合并公共模块。

## 05 尚待确认及本轮未处理范围

| 事项 | 已明确的边界 | 仍需确认的业务/企业事实 |
|---|---|---|
| 必需/可选依赖与业务降级 | 场景决定领域限制，O01决定整体报告状态；A01不做业务决策 | 各场景和联合目标的依赖矩阵，哪些缺项允许部分/RULES_ONLY，哪些必须阻断结论或建议 |
| 任务预算 | 默认并行2/重规划1，版本化有效配置，模型/用户不能自行放宽 | 业务是否接受初始默认值；工具、时长、费用阈值，压测和质量依据 |
| 证据与历史可追溯性 | D03/D04/O01引用而不重复维护资产 | 源数据/派生产物留存、删除/撤权要求，以及历史报告引用不可解析时的产品处理方式 |
| 数据及业务口径 | 保留现有权威域、窗口与指标归属 | 实际厂商接口、映射、库存时效、投诉窗口、费用与汇率来源，沿用需求第16节待评审清单 |
| 有限写入 | 仍仅开放经审批的采购草稿/内部工单；C03独占写入 | ERP/CRM当前条件校验、可靠幂等、回执查询及各动作授权人是否具备 |
| I01具体实现 | 仅承载实际需求，不预先要求新产品或通用接口族 | 哪些现有设施可复用、文件和检索的实际规模与接入需求 |
