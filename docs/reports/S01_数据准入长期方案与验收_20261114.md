## A—E 独立比较

“有效业务日”应定义为：已完成的业务日、指定实体范围、查询覆盖和业务语义获证明。**零销量可有效；缺记录不自动有效；不是“有订单的日子”。** 营业日/日历日也必须明确：当前7日为连续自然日，不能擅自只挑工作日。以下都不修改B01/B02公式。

| 方案 | 统计意义和优点 | 缺陷/风险 | 适合场景与成本 |
|---|---|---|---|
| A：15天取最近7有效日 | 避开缺失日，规则直观，样本数固定 | 7天可能横跨两周、跳过全部未知或只保留高销量日；与“7日平均”易混淆，周末/促销分布偏差。7/15覆盖仅46.7%，不能仅因够7日就赋确定性；不能修库存对账 | 数据缺失随机且运营特征已核实的参考；工程小、业务误导风险较高 |
| B：可配置滚动窗口 | 观察天数、最少有效数、缺失率、最新覆盖、最旧样本年龄分开；使用窗口内全部有效日可减挑样偏差 | 参数过多易任意调到通过；缺失通常非随机，10天平均不能声明15天真实均值。仍须覆盖证明/版本冻结 | 现有ForecastPolicy渐进扩展；成本中，必须固定默认及改版审计 |
| C：有效历史区间+当前可信库存 | 将需求估计与库存基准分离，合法补货入库不使销量预测天然失败；适合教学历史复用 | 旧需求未必代表现在；新库存观察可信不等于历史争议已消失。不得把当前库存+历史销量反推期初并声称对账通过 | 当前问题关键技术部分；成本中，需可信基点与时效契约 |
| D：分级准入 | 事实展示→参考趋势→确定性数量→人工提交，单域失败不吞掉所有有用信息 | 单一等级不足表达各域能力：可以有参考来源但满足方案B人工请购，不能机械要求所有人经过第3级 | 现有D03 affects/CANDIDATES可复用；成本中，前端要说明不同输出能力 |
| E：推荐混合：独立时间域+可信基点+能力门 | B的有限参数、C的库存基点、D的分域能力；默认保持7完整日SMA，不新造综合分/统计模型。长期完整零观测正常工作 | 须防“重置基点”掩盖未知移动；窗口外异常仅能在新基点获独立证据后隔离。需求陈旧必须降级 | 当前FastAPI/MySQL/Vue/Worker适合；中等改造，先正确性再体验，无数仓/MQ/流处理 |

离线量化比较：15天内10个已知日的样本（最近为1、向过去递增到10），“最近7有效日”均值4，“全部10有效日”均值5.5；差异37.5%，不能称为相同7日SMA。15天仅7有效日的比较样本，A会给数值，但有8天未知，推荐只作参考。连续3个**有完整观察证据**的零日与12个4件日合计48/15=3.2，不得丢零后算4。最近3日未知、此前12日已知，即使缺失率20%，最新样本年龄4日，仍须降级。

**判断：不推荐将A作为默认准入规则。** 它没有解决本次累计库存口径问题，也不能证明缺失日随机。更简单的首版是修时间域、保留现有7完整日教学策略、加入参考降级和能力拆分；自适应15日策略后置，由真实缺失样本验证后再批准。

## 推荐E的最小设计

### 三个互相独立的时间域

1. **需求观测域**：`businessTimezone`、显式`businessDate`、`windowStart/windowEnd`，按批准的订单/履约需求业务日期分组；每天有`KNOWN_SALES / KNOWN_ZERO / UNKNOWN / CENSORED`及覆盖证据。默认最近7完整自然日，全7日已知才作为当前确定性教学需求。少于7日仍展示已知趋势与不足原因，不自动补零、不移动日期。
2. **库存对账域**：版本化基点`stockCheckpoint`的真实ERP库存桶/单位、quantity/available/reserved语义、独立读取时间、源行更新时间和关联证据；从`postingWatermark`到当前观察边界检查**全部合法移动**，不跟随需求窗口裁剪。等式为`Q_now = Q_checkpoint + Σ(posted delta)`；available另核预留/释放，不把已发货历史再从当前available扣一次。
3. **未来供需域**：把可信当前NET_AVAILABLE、经批准需求曲线、逐行有效剩余及可靠可售日期传给既有B01。D1_AFTER_D0与当天余量限制保持；ERP建议的时间域另列UNKNOWN，不能与平台预测暗中合并。

新的分析始终联网取当前事实；任务内恢复沿原asOf不等于新分析。`observedAt`是读到时间，`rowUpdatedAt`是源记录变更时间，`asOf`是分析事实边界，`completedAt`是真实采集完成；不能继续互相替代。固定时区由策略统一提供给采集和投影，明确定义`[start,end)`，源接口端点实际语义先契约验证，再过滤。读取跨日则冻结显式businessDate并标完成时间/偏移，超允许采集时长或库存前后不一致须停止数量输出并要求新采集。

### 基点的可信条件及异常隔离

基点不是每次`opening=current+sales`，也不是遇差额就清零。首次可复用已核验教学期初及**全链**作为历史基点；随后当前库存前后独立读一致、身份/桶/单位/预留语义明确、相关期间流水分页完整、逐事件父子关系及算术验证后，才建立新版本。若ERP无完整流水能力，可在负责人明确批准的“直接可信当前库存”模式下建立**新当前基点**，记录历史未闭合区间/差额/原因及隔离决定，不能把它标为历史对账PASS。企业模式是否接受该证据需业务签认，本轮不代签。

有完整新基点后，基点前不影响当前数量的旧问题保留历史质量警告；基点后身份错配、重复过账、不明库存差额、语义未知仍BLOCK确定性数量。需求样本所在区间受历史库存异常影响时，不能仅靠新基点恢复需求可信度，必须降级为历史情景。一个域的证据无法代签另一个域。

退货、入库、库存调整、调拨及反转分别接入真实事件：只有实物退回且可售过账才增加available，退款不自动加库存；采购到货只减在途剩余，正式库存过账后才进库存。使用稳定`ERP event ID + line/bucket ID + reversal ID`去重与关联，同一已收数量不能既在库存又在有效在途。缺逐行剩余/可售ETA则不抵扣，显示未知影响。仅教学内部合法事件，任何新增真实动作需另批，禁止直接ERP数据库。

### 能力层级与默认策略

| 能力 | 最小事实 | 输出及限制 |
|---|---|---|
| 1 基础事实展示 | 身份及可读字段、采集状态 | 当前已知库存/订单/来源；未核验字段为未知，不合计成权威量 |
| 2 趋势/历史参考 | 明确有效样本及时间域 | 均值/样本分布、旧需求情景；库存不可靠时不算当前缺口；禁止标当前确定性建议 |
| 3a 当前风险/需求数量 | 当前库存可信、需求策略满足、明确分析时域 | 即使报价/MOQ缺失仍能由原B01计算指定已知时域风险。若交期未知，只显示批准覆盖时域的风险，不杜撰采购时点 |
| 3b 规则补货候选 | 3a及明确采购规划参数、质量候选门 | 原B02给MOQ/整箱候选及其到货情景，不授予执行权限 |
| 4 人工请购 | 独立权限/范围/必要采购门及最新复核 | 保留V2方案B：ERP参考本身不禁人工提交；参考身份/未知须知情确认。不能靠等级3自动开放采购 |

工程上用现有issue的affects，加`capabilities`布尔/原因与`domainQuality`（需求、库存、供应、报价分列），不做一个可相互抵消的总分。硬错误不会被高样本数“加分覆盖”。D03/B01/B02已有baseline和candidates分离，离线合成输入移除MOQ/倍数/maxQty/候选日期后，**原B01仍给相同缺口与风险，B02候选为空**，无需修改公式；生产D02目前尚未提供该路径。

建议默认仅保持`windowDays=7,minKnownDays=7,maxMissingRatio=0, latestKnownDay=D−1`，这是批准前提下的新零日证明方式，不是放宽。数据不够时优先展示过去最近一段可靠区间；15日只作寻找参考样本的上限，不“挑满7日”。备选实验B可用15日全部已知日、min7/缺失≤20%/最新年龄≤2日作为**待验证参数**（实际上至少12/15日），但其非随机缺失风险和季节性未获验证，首版不升级为当前确定性策略。

历史情景默认展示最近可靠7日的平均和最后覆盖日；超过15日再显著标“旧销量情景”，超过30日默认只显示历史，用户显式查看才做带新库存的条件估算。15/30是建议产品提醒阈值，不是已签认业务规律；范围外仍可查看不可变原报告。任何旧情景数量不得自动继承采购依据；若未来允许人工参考请购，须单独确认该来源类别并保留全部方案B门。

## 长期复用的七个业务回答

1. **几天没有订单**：若新ERP读取证明每日范围完整、SKU正常可售且无被截断需求，则是有效零日，7日均值自然下降；原历史不删除，零需求时应显示当前窗口无需补货，不等于永久无需求。若平台仅保存了7单ID、ERP不能证明无单，缺失日仍未知，降级而非填零。
2. **15天不足7有效日**：显示样本数/区间/未知天数；只给参考趋势，或在库存可信时做明确假设的历史需求情景，不生成冒充当前确定性数量。冷启动新品应明确冷启动，不以MOQ反推销量。
3. **销量已超过15天、库存当前可读**：可以新建“以某历史均值为条件、使用当前库存”的参考情景；不能把历史报告库存/建议直接搬来。样本可能过季/促销，默认时效分级并提示补充近期覆盖。
4. **库存变化、销售不变**：先找真实入库/退货/调整/调拨/预留事件，守恒通过后升版基点；未解释差额保留阻断，不能一键洗掉。不频繁重建SKU。
5. **退货/入库/调整**：按posting域进库存守恒；销售净退货是否冲回原需求期或计当日须另签策略，保留毛履约/退款/实物退货各字段，不能双扣双加。
6. **报价过期**：不抹掉可靠需求与不依赖报价的风险；限制合规采购候选/人工提交，报价更新后用新事实再验证。未知交期不提供可靠到货效果结论。
7. **少量合法增量验证**：可以在获准自有范围按需增加一笔真实订单/退货/入库/调整作为事件测试，记录批次、真实ID、幂等键、回读与预期守恒；不按日制造销售，不为了均值补数据，事件为0的日期也需测试。没有当前写授权时只离线设计，不执行。

**多久可用？** 不是SKU创建后固定7/15/30天过期。当前可信库存与每日范围持续可证明、策略/权限有效且无未解释事件时，可按滚动规则持续运行，纯无新增事件的30日离线模拟可计算并逐步变0；未证明真实连续30天ERP可用，更不承诺无限保证。若只有冻结历史而没有新的覆盖证据，当前确定性资格会随新鲜度下降，默认次日缺覆盖即降级，历史报告仍可长期查看。由是否持续获得可信观测决定，不能由“SKU合法创建过”保证。

## 前端原型建议（不实施）

列表主状态用“规则建议 / 无需补货 / ERP参考 / 历史需求参考 / 数据待补全”，旁边分别标需求、库存可信度。详情首屏显示“11/07—11/13，7个完整日，其中3日无销售；缺失0日”，而不是“有销量4天所以失败”。15日候选若启用，显示采用天数、未知日、均值分母、跨度、最新覆盖日，能查看每天状态。

库存展示“ERP当前可用6件，09:44核验；源最后变更11/13；对账基点已验证/未闭合”，避免把源旧更新时间误称旧库存。规则/ERP参考分别显示，ERP未知周期/在途抵扣清楚提示。错误主文案例如“库存基准与销售范围不一致，暂不能给出当前规则数量；已保留历史分析”，再给“查看数据范围 / 查看历史报告 / 重新获取事实 / 联系负责人核对变动”。诊断代码、快照ID收在证据折叠项。

新失败报告不能覆盖历史成功卡片；历史明确日期、当时库存和策略，并注明“历史结果”。若参考情景可用，按钮“按历史销量查看条件估算”，不称“恢复昨日建议”。缺报价时仍可看风险，采购按钮说明“报价已过期，请更新报价后重新核验”；不能把内核异常长串作为用户恢复指导。

## 跨日期验收与本轮对比验证

固定历史回归：隔离夹具、显式asOf、固定输入和版本，网络/模型/写入皆关闭，重复运行结果相同。跨日模拟仅改变测试输入日期/采集过滤，**不改系统日期**。动态仿真：真实时间、真实ERP正式接口、独立批次/成员、每日只读获取最新事实；不自动每日造单。两套结果分别存证，不能拿30日模拟冒充30天真实运行。

| 必验场景 | 本轮实际验证 | 改造后验收要求 |
|---|---|---|
| 7天完整销量 | 原normalizer/B01/B02，39件→48件候选 | 原Golden/两SKU原报告结果保持，杯无候选 |
| 15天7有效 | 原型A有均值，E仅参考（8未知） | 不把跳样升级为完整7日；每日状态/来源可查 |
| 15天10有效 | 最近7均值4，全部10均值5.5 | 明确分母及采用天，未知不能填零 |
| 15天不足7 | 原型降级参考 | 无伪当前建议，事实/旧报告仍可读 |
| 连续3天真零 | 原型15日均值3.2，零计有效 | 覆盖证据齐，零纳分母；无单不是接口失败 |

## 白话总结（不超过1000字）

现在最不合理的地方，是把“最近一周卖了多少”和“从最初库存到现在总共扣了多少”当成同一份数据。昨天7张订单都在查询范围内，45减39正好剩6，100减19剩81；今天第一天的订单被窗口移走了，却仍拿最初45和100对账，于是多出4件和2件。已核对的库存、登记订单及保留流水没变，不是商品隔夜坏了。

15天选7天不是最佳修复：它只会推迟同样的错误，还可能漏掉零销量日、偏向有销量日。更稳妥的是把可靠销量区间、当前可信库存、采购资格分开。先保留最近7个完整日的现有策略；能证明没卖就是零，证明不了就是未知；数据不够仍能看事实、历史和有明确假设的参考。报价过期只限制相应采购能力，不该让可靠销量和风险一起消失。

核心要改D01采集窗口和覆盖证明、D02库存基点与需求投影、D03质量/时间证据，以及V2结果/API展示；前端随后统一评审，不必改B01/B02公式或引入新平台。真实身份与单位、库存守恒、未知在途不抵扣、有效报价、MOQ整箱、权限、人工确认、幂等回读和ERP审批边界必须保留。

新SKU没有新业务事件也不应固定几天就失效：只要持续从ERP证明库存可信、每日完整无单且可售，就能滚动分析，均值会自然降为零。30天离线已验证这种逻辑，但没有30天真实运行保证。若只有冻结旧数据，不能证明后来几天是否有单，应降级为历史参考；历史报告仍可查，不能冒充最新建议。采用方案仍需负责人批准，本轮只交评审材料。
